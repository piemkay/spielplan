## 1. Why these are one milestone

`docs/spielplan-spec_v2.1.md` is named by twenty findings and `docs/spec-v2.2-proposals.md` by
twelve. Eleven agents amending one normative markdown file in parallel is the worst merge
surface in this repository — a conflicted paragraph in a spec is not a merge conflict, it is two
readings of a requirement, and the loser is silently correct. So one milestone owns those two
files plus `docs/TESTING.md`, `CLAUDE.md`, README's *Running it* block and the **structural**
half of `backend/tests/spec_coverage.toml` — waivers, `current_milestone`, and the gate code in
`test_spec_coverage.py`. Every other milestone in this release is restricted to appending or
editing the rows for its own requirements.

Running last is not scheduling convenience, it is a correctness requirement in two places:

- **arch-13's residue baseline cannot be written before the code moves.** The guard records
  today's raw-SQL statement counts per `api/` module and asserts them both *not grown* and *not
  stale*. Measured on this tree: `setup.py` 12, `auth.py` 9, `tonight.py` 7, `push.py` 4,
  `library.py` 4, `admin.py` 3, `state.py` 2, `passkeys.py` 1, `artifacts.py` 1 — 43 across nine
  modules. `arch-06` empties `api/tonight.py` into `tonight/play.settle`; the moment it lands,
  a `tonight.py: 7` entry is a *stale* entry and the guard is red on arrival. Baselined after,
  the guard can only tighten.
- **test-13's release gate is defined over the spec and e2e inventory M4.12 changes.** M4.12
  deletes `frontend/src/routes/tv`, `e2e/specs/16-tonight-tv.spec.js` and the coverage row
  `tonight-rank-tv-kiosk-route` with its five named tests. A release workflow that enumerates
  e2e legs, and an executed-coverage gate that reads a Playwright report, both have to be
  written against the inventory that survives.

The rest coheres for one reason: every finding here is a **claim the project makes about
itself**. A spec sentence describing a surface that does not exist, a coverage row whose `what`
outruns its tests, a report that hides a waiver, a milestone bullet a grep disproves, a `18/18`
that contains a `check(True, …)` — these are the same defect at five altitudes, and the repair
is the same move: measure, then write down what was measured.

## 8. Risks and gotchas

**Merge surface.** This milestone edits the two files eleven other agents cite. Every edit is a
line edit; nothing is reformatted, restructured or rewritten wholesale. `git diff` on
`docs/spec-v2.2-proposals.md` already warns that LF will be replaced by CRLF — an editor that
normalises line endings turns a six-line amendment into a 2,000-line diff nobody can review.

**Opening too early.** `current_milestone = "M4.16"` arms M4.6–M4.15 simultaneously. Verify every
earlier gate is green first, or the red gate stops being a plan and becomes noise.

**Baselines that are stale on arrival.** `ALLOWED_RESIDUE` must be measured on the tree at write
time, not copied from §2 of this document. `arch-06` empties `api/tonight.py`; `push/send.py:43`'s
import inversion is another milestone's fix. The *not stale* half of the assertion is what makes
that safe — and what makes it fail loudly if the code moved after the baseline was taken.

**`e2e/specs/05-milestones.spec.js` fails by design.** Its `for` loop at `:24` gives the file its
`::*` wildcard, and `:79` (`Account is built`) and `:89-97` (the admin tab sweep, which asserts
`Users` and `System` are still placeholders) both sit exactly where Phase J's attribution block and
M4.6's Users tab land. Budget those assertions into the diff rather than discovering them when the
e2e leg goes red. E2E specs are stateful, filename-ordered and single-worker: extend an existing
spec, do not add a file out of sequence.

**ASCII only.** The coverage report prints to whatever console the developer has, and
`test_spec_coverage.py:167-168` already carries the comment explaining why: a Windows cp1252
terminal turns a decorative glyph into a crash. The new waived-ids line lengthens that output —
keep it plain and keep it under a sensible width.

**Line length 108 and no wholesale reformatting.** `ruff check .` runs from the repo root (the root
`ruff.toml` widens scope to `ops/`), `ruff format` is informational only, and the 108-column limit
exists so quoted spec sentences do not wrap. Do not reformat adjacent code.

**Never edit an applied migration.** `0004_dna.sql:11`'s wrong reference is repaired by a docstring
elsewhere. The sha256 check is a hard startup error, and a "harmless comment fix" bricks every
existing install.

**The gate must not degrade quietly.** `_pytest_ids` intersecting with `git ls-files` introduces a
subprocess. If it fails, fail — a fallback that silently reverts to globbing recreates precisely
the hole this milestone closes. The same rule governs the release workflow: a leg that skips its
whole body fails the job.

**Do not edit a row to fit the code.** `M4-open-points.md:212-213` states it and this milestone is
the one most tempted to break it, because its whole job is reconciling documents with reality. The
direction is always: measure, take the decision, amend the spec, then re-point the row. A row whose
`what` the owner has not agreed to change stays as written and stays red.
