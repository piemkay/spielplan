# M5.2 — the trigger: every add the household told us about

> **This is a proposal, not an amendment.** Decisions **323, 327** and **332, 333** are recorded in
> [`ROADMAP-M5.md`](ROADMAP-M5.md#decisions-the-owner-must-take-numbered-from-321). 327 changes a
> §7.2 sentence, and only **M5.1** edits the spec file.

§7.2 is titled with its owner requirement — "every Jellyfin add triggers acquisition"
(`docs/spielplan-spec_v2.1.md:342`) — and is a promise about *arrival*: two intake paths, a debounce
because library scans add seasons in bursts, and one acquisition job per new title. Its third bullet
also makes both paths responsible for `is_owned = false`, "re-derived from Jellyfin, never trusted
stale" (`:346`).

Both paths are absent. `DateCreated` is requested by the connector and read by nothing; the test
double emits no `DateCreated`, no `Episode` item and no webhook at all; `library_ids` is stored,
served to the admin API and used by no read; and there is no library-wide watermark, because the
migration that would have carried one deliberately declined to (`0006_jellyfin.sql:9-11`). What
*is* shipped is the half §7.2's third bullet actually needs — a doubly-gated ownership falsifier
that refuses to act on anything but a complete library read.

This milestone builds the two intake paths, reconciles them with that falsifier, and teaches the
test double to emit the shapes a real server sends. It ships **no UI**: the Jellyfin card's webhook
status and library pick are M5.7's, for the same reason M4.15 restyled surfaces only after the
backends stopped moving.

---

## 1. Why these are one milestone

**Two paths, one observable.** Coverage row
`jellyfin-acquisition-eval-new-title-trigger-one-job-per-title` (`spec_coverage.toml:3180-3188`)
asserts *both* paths and the ownership flip in one sentence: a burst inside the debounce yields one
job; with the webhook absent the delta poll enqueues the same set once; a title absent from the
mirror flips `is_owned = false` and flips back. That row is one milestone's gate by construction —
it cannot be closed by half the work.

**They share the resolver and they share the fallback relationship.** "Fallback" means the delta
poll must produce the same enqueue the webhook would have, for the same title, without duplicating
it. The only way to hold that is to have one enqueue path with two feeders, which means one
milestone.

**And they share four files nobody else may touch.** `connectors/jellyfin.py` (the delta read),
`connectors/resolve.py` (Episode to Series, and the unmatched report M5.3 consumes),
`sync/seen.py` (the sweep that owns falsification) and `ops/fake_jellyfin.py` (the double that must
learn three new shapes). The file-locality test gives all four to this milestone and to no other.

**Depends on:** M5.1 — the durable queue it enqueues into, and the `/events` namespace M5.1 routes
past the SPA fallback and mounts empty. **Parallel with:** M5.3, M5.4, M5.5.

## 2. What does not exist today

### 2.1 The Jellyfin client has no delta read and no library scoping

`connectors/jellyfin.py` (540 lines) is the whole §7.1 read surface, ported and hardened.
`FIELDS` at `:30-33` already includes `DateCreated`, and the comment at `:28-29` says why: *"carries
Played/PlaybackPositionTicks for the seen sync (§7.3), DateCreated drives the §7.2 delta poll at
M5."* **`grep -rn DateCreated backend/spielplan/` finds three hits, all in that file, and none is a
reader.**

What is absent:

* No method taking a `MinDateLastSaved` / `DateCreated` filter, and no "what changed since" call at
  all. `all_items(jf_user_id, page=500)` (`:338-411`) is a hardened full walk that **raises rather
  than truncating**, which is load-bearing for §2.4 below.
* `ITEM_TYPES = "Movie,Series"` (`:34`) — no `Episode`. So a webhook burst of episodes carries item
  ids this client's own reads never see.
* No `/Library/MediaFolders` call and no per-library scoping. `JellyfinConfig.library_ids`
  (`connectors/registry.py:50`) is stored (`:344`), merged on save (`:319`), loaded (`:233`) and
  served to the admin API (`api/admin.py:170`) — and `grep -n "ParentId\|parentId\|MediaFolders"
  backend/spielplan/connectors/jellyfin.py` returns **nothing**. The pick exists as a value with no
  consumer.
* The client is constructed per call (`registry.make_client`) and is stateless between polls, so a
  watermark has nowhere to live inside it.

### 2.2 There is no library-wide `DateCreated` watermark, and the omission was argued

`0006_jellyfin.sql:9-11`, verbatim:

> "The sync watermark that looks like it belongs here is deliberately absent: `user_title` carries
> `jf_synced_at` per title already, and that column is what separates 'the app has an explicit
> action Jellyfin has not seen' from 'Jellyfin changed after we last agreed'."

That is per-(user, title) seen-state, not a library-wide "everything created after T". M5.2 must add
one, and **where** it lives is part of the plan (§5): a new table, or one key in
`connector_config`'s `jellyfin` config — the latter because it is connector state rather than
household data, and `connector_config` already exists for exactly that (`0001_system.sql:22-30`).

### 2.3 There is no webhook, no debounce, and no durable pending set

`grep -rn "webhook" backend/spielplan/` finds the word only in comments and in
`frontend/src/routes/admin/connectors/+page.svelte:326` ("Library pick and webhook status arrive
with M5 (§7.2)"). There is no route, no token, no signature check, no `ItemAdded` shape, no
debounce and no pending set.

Three things the spec does not settle (**decision 333**):

1. **The debounce key** — per item, per resolved series, per library, or global.
2. **Fixed or sliding window.** A sliding window lets a long scan postpone acquisition
   indefinitely; a fixed one acquires while the scan is still running.
3. **Where the pending set survives a worker restart.** §5.3 files every job as durable, and a
   restart inside the ten-minute window must not drop the burst.

The clause welds two rules into one sentence and only the second is fully specified: *"series
acquire per-show, not per-episode"* is unambiguous, and the Episode-to-Series idiom already exists
in the tree (`sync/playback.py` reads `SeriesId`; `ops/fake_jellyfin.py:58-60` documents that "a
session on one plays an **Episode**, with its own `Id`, a `SeriesId` for the folder").

### 2.4 The ownership half is shipped, and the delta path cannot discharge it

`sync/seen.py:1117-1139` (`_falsify_ownership`) is §7.2's third bullet, already built and **gated
twice** — its own docstring calls it *"the most destructive statement in the module — a bug here
un-owns the household's whole library and empties Tonight's pool"*. The gates are: the caller
returns on a failed library read; `all_items` raises rather than truncating; and an empty resolution
is refused, *"because a library that resolved to nothing is a read that did not really happen
rather than a household that owns nothing"*. `connectors/resolve.py:311-335`
(`prune_missing_items`) applies the same rule to the copy map.

**A `DateCreated >` delta poll is an add detector and by construction never sees a removal.** So
§7.2's third bullet, which makes *both* paths responsible, cannot be honoured by the delta path.
That is **decision 327**, and the recommended ruling is that falsification stays with the existing
full sweep alone and §7.2's bullet is amended in place to say so.

The flip *back* on is already handled: `resolve.upsert_item` (`:182-263`) sets `is_owned = true` and
`owned_checked_at` under an hourly write guard for any item that resolves.

### 2.5 The unmatched report is names only, and its consumer is M5.3

`ResolveReport.unmatched` is `list[str]` and `upsert_item` appends
`str(item.get("Name") or item.get("Id") or "?")` (`resolve.py:197`). `as_dict` sends
`len(unmatched)` plus `unmatched_names[:20]` (`:74-75`). The comment at `resolve.py:147-149` says
this list is *"`report.unmatched`, which §7.2's acquisition half consumes at M5"* — but a name is
not enough to acquire from: the consumer needs the item's `ProviderIds`, which means either widening
the report or re-reading the item.

`frontend/src/routes/admin/connectors/+page.svelte:308` renders the same idea: *"§7.2's refused
matches, which M5's acquisition pipeline consumes"*.

### 2.6 The test double emits none of the three shapes this milestone needs

`ops/fake_jellyfin.py` serves `/System/Info/Public`, `/Users`, `/Items`, `/Shows/{id}/Episodes`,
`/Sessions`, `/Users/AuthenticateByName` and `/UserPlayedItems/{id}`, plus a `control` router
(`/reset`, `/played`, `/session`, `/sessions/clear`, `/state`). `ITEMS` (`:38-57`) carries seven
items and **no `DateCreated` on any of them**; there is no `Episode` in `/Items`; and there is no
webhook emitter and no control route that would fire one.

CLAUDE.md's rule governs the extension: *"Test doubles are refusers, not mocks"*. The fake already
rejects the admin key on the Played write on purpose. Its `ItemAdded` emitter should be a refuser
too — it must be able to emit a burst, an out-of-order event, an event for an unpicked library and
an event whose payload lacks the field the handler relies on.

### 2.7 `/api/events/jellyfin` is not an ordinary route and the guards know it

`test_route_inventory.py:75-98` — the `ANONYMOUS` frozenset, nine entries, each carrying its reason.
A token-authed webhook is not session-authed, so it must be added here with its reason, and the
"untested set may only shrink" ratchet (`:100+`) means it arrives with a test naming it.

## 3. Owner decisions this milestone cannot take alone

**Decision 327 — which path owns `is_owned = false`?** Blocks the sweep reconciliation (Phase D) and
changes a §7.2 sentence. Evidence in §2.4. Recommended: the full sweep alone. If the owner instead
wants the delta path to falsify, that path needs a complete read, which makes it not a delta poll —
say so rather than building a weaker falsifier beside a stronger one.

**Decision 333 — the debounce's key, window and durability.** Blocks Phase B. Recommended shape: a
durable intake table with a `resolved_key` (series id for an Episode, item id otherwise) and
`not_before = received_at + 10 min`, swept by the worker loop; a later event for the same key
**extends nothing** (fixed window), so a long scan cannot postpone acquisition indefinitely.

**Decision 332 — the token, the failure answers and the `/events` routing.** Owned jointly with
M5.1, which makes the routing change. M5.2 needs the token's home and the bad-token answer settled
before Phase A. Recommended: a `connector_config` secret under `jellyfin`, generated at first save
and displayed once; 401 on a wrong token; 503 naming `SECRETS_UNREADABLE_REASON` on a `SECRETS_KEY`
failure (`connectors/registry.py` already carries `secrets_unreadable` for exactly this degradation,
`:65-66`).

**One more, small and real: does an add in an unpicked library enqueue?** §7.2's heading says "every
Jellyfin add triggers acquisition", and §6.6 gives the admin a library pick. Recommended reading:
the pick is the ownership boundary, the heading means "every add the household told the app about",
and an event outside the pick is **recorded and not enqueued**, with the card saying so. Fold this
into decision 327's entry or take it as its own; it is the difference between the coverage row's
last clause passing and the household being billed for a library it deselected.

## 4. The work, in order

### Phase A — the webhook

**A1. `api/events.py`** gains `POST /events/jellyfin`. M5.1 mounted the module empty and taught
`SpaFallback` to decline the namespace; this fills it. Token-authed per decision 332; add the route
to `test_route_inventory.py`'s `ANONYMOUS` with its reason in the same commit as its test.

**A2. Payload tolerance.** The Jellyfin Webhook plugin sends an **operator-configured template**, so
no clause fixes the fields. Require the minimum the handler can act on (`ItemId`, `ItemType`), treat
everything else as advisory, and answer **202 for an unparseable body rather than 400** — a webhook
the app rejects is one the operator never learns about. Publish the template text the operator
pastes into the plugin the way `.env.example` publishes config; that file is the contract.

**A3. Episode to Series.** An `ItemAdded` whose `ItemType` is `Episode` resolves to its `SeriesId`
and the job is the show's. The idiom exists (`sync/playback.py`); the new part is doing it from a
webhook payload rather than from a session.

**A4. Record, then debounce.** The handler's only synchronous work is writing the intake row. Every
decision — is this library picked, does this resolve, is it already owned — happens in the worker,
because the handler answers a server that will not retry.

### Phase B — the debounce

**B1. `acquire/intake.py`** — the durable pending set decision 333 chooses, with a `resolved_key`
and a `not_before`, swept by a worker job. **A worker restart inside the window must not drop the
burst**; that is the whole reason the set is a table and not a dict.

**B2. One job per resolved key.** The sweep collapses the window's events for one key into a single
`acquire.queue.enqueue(kind, key)` call. M5.1's queue makes this free: identity is `(kind, key)` and
enqueueing the same pair twice is a no-op (`mdc/queue.py:7-8`).

**B3. The library pick is applied here**, not in the handler: an event for an item outside
`JellyfinConfig.library_ids` is recorded with that reason and not enqueued. This is the first reader
`library_ids` has ever had.

### Phase C — the delta poll

**C1. A delta read on the client.** `connectors/jellyfin.py` gains one method: items created after a
timestamp, scoped to the picked libraries. Keep it beside `all_items` and keep `all_items`'s three
bounds — the new method is an *addition*, and nothing about the full walk may be relaxed, because
§2.4's falsifier depends on it raising rather than truncating.

**C2. `/Library/MediaFolders`**, so §6.6's pick has something to pick from. M5.7 renders it; M5.2
supplies the read.

**C3. The watermark.** Per §5 below. Initialise it on a fresh install to the install's own creation
time, not to epoch, or the first poll enqueues the entire library.

**C4. A 15-minute job** in `worker.py`'s registry — **registered by M5.1**, which owns that file.
M5.2 exports the callable and M5.1's Phase C4 drain entry or a sibling registers it. If M5.1 has
already landed, a one-line registration is an acceptable exception, but the entry's budget paragraph
is M5.1's convention to follow.

**C5. Re-enqueue is a no-op, by two mechanisms.** The watermark advances only on a completed read,
and the queue's `(kind, key)` identity absorbs the overlap. Both, because the first is a promise
about the poll and the second is a property of the queue, and the coverage row asserts the
observable rather than either mechanism.

### Phase D — reconciling the two paths with the sweep

**D1. Do not re-implement falsification.** `_falsify_ownership` (`sync/seen.py:1117`) and
`prune_missing_items` (`resolve.py:311`) are shipped, gated twice and named in §12's M4.11
criterion. Per decision 327, the delta poll writes no ownership at all.

**D2. Flip back on stays where it is.** `resolve.upsert_item` sets `is_owned = true` for any item
that resolves (`:211-233`); a re-added title flips back through the ordinary sweep. The coverage
row's "flips back when re-added" is therefore a test of the *existing* path, and should be written
as one rather than as new behaviour.

**D3. The unmatched report gains what its consumer needs.** Either widen `ResolveReport.unmatched`
from `list[str]` to carry the item's `ProviderIds` and `Id`, or have the acquisition path re-read
the item. Widening is cheaper and honest, but `as_dict` (`:66-77`) is a wire shape the admin card
renders and truncates at twenty — keep the wire shape as it is and widen only the in-memory field.

### Phase E — the double

**E1. `DateCreated` on every item in `ops/fake_jellyfin.py:38-57`**, and honoured by `/Items` when
the delta filter is present.

**E2. `Episode` items** with `SeriesId`, so a burst can be emitted and so `ITEM_TYPES`'s exclusion
of `Episode` is exercised rather than assumed.

**E3. An `ItemAdded` emitter on the `control` router** that POSTs to the app's webhook. It is a
**refuser**: it can emit a burst of twelve episodes inside one window, an event for an unpicked
library, an event with a missing field, and an event with a bad token — all on purpose, the way the
fake already rejects the admin key on the Played write.

**E4. A library shape.** `/Library/MediaFolders` with at least two libraries, so "an add in a
library the admin did not pick" is testable.

## 5. Schema changes

**`0025_jellyfin_delta.sql`, or none.** Take the number from
[`ROADMAP-M5.md`'s ledger](ROADMAP-M5.md#the-migration-ledger).

Two candidates, and **decision 333** plus the watermark question decide whether either is needed:

* **The webhook intake table** — `(id, received_at, raw jsonb, item_id, item_type, resolved_key,
  not_before, state)`. Needed unless decision 333 puts the pending set inside M5.1's
  `acquisition_task` with a `defer`, which is a legitimate alternative: a task deferred to
  `now() + 10 min`, re-enqueued by key, is a fixed-window debounce with no new table. **Prefer that
  if the queue's `defer` semantics allow an extend-nothing re-enqueue** — fewer tables, and the
  durability argument is already made.
* **The `DateCreated` watermark** — one library-wide timestamp. Recommended home: the `jellyfin`
  row in `connector_config` (`0001_system.sql:22-30`), because it is connector state rather than
  household data and needs no DDL. `connectors/registry.py:203-213` already does the sealed
  read-modify-write under `FOR UPDATE` for exactly this shape.

If both land in `connector_config` and in the queue, **M5.2 writes no migration and says so** — the
behaviour `ROADMAP-to-M5.md:288-290` names as the one to copy.

**Never edit `0006_jellyfin.sql`.** Its deliberate omission of a watermark (`:9-11`) is an argument
in an applied, checksummed file; the new watermark's home is argued in the new file or in a comment
where it lands.

## 7. Exit criterion, as something to run

> On a real install against the fake Jellyfin: a burst of twelve `ItemAdded` events for twelve
> episodes of one series, delivered inside the 10-minute window, yields **one** acquisition job for
> the show and none for any episode — and still yields one when the worker is restarted at minute
> five. With the webhook plugin absent, the 15-minute delta poll enqueues the same set exactly once
> and enqueues nothing on the following poll. A title present in the database and absent from the
> current mirror flips `is_owned = false` through the full sweep, and flips back when it is
> re-added. An `ItemAdded` for an item in a library the admin did not pick is recorded with that
> reason and enqueues nothing. A wrong token is refused and enqueues nothing.

Write the checks into `ops/m52_exit_criterion.py`, or into `ops/m5_exit_criterion.py` as its second
section if decision 331 keeps one script for the whole milestone set. Either way it **refuses to run
on the fixture**, for the same reason M4.5's and M4.12's do.

| # | measure | pass |
|---|---|---|
| 1 | 12 `ItemAdded` for one series, one window | `SELECT count(*) FROM acquisition_task WHERE kind='acquire'` = 1 |
| 2 | same, worker restarted at t+5 min | still 1 |
| 3 | webhook off, one delta poll | the same key set, each once |
| 4 | second delta poll, nothing added | zero new tasks |
| 5 | delta poll after a **failed** read | watermark unchanged |
| 6 | title removed from the mirror, full sweep | `is_owned = false` |
| 7 | title re-added, full sweep | `is_owned = true` |
| 8 | `ItemAdded` in an unpicked library | recorded; zero tasks |
| 9 | `ItemAdded` with a wrong token | 401; zero tasks; nothing recorded as pending |
| 10 | `ItemAdded` with a missing field | 202; recorded; no 500 in the log |
| 11 | after all of the above | no ownership write from the delta path at all |

## 8. What this milestone deliberately does NOT do

* **It does not build any UI.** The Jellyfin card's webhook status and library pick are **M5.7's**
  (`admin/connectors/+page.svelte:326` is the placeholder they delete). M5.2 ships the API and the

* **It does not build the acquisition pipeline.** It enqueues into **M5.1's** queue and stops.
  Whether the job then fetches anything is M5.3's.
* **It does not touch `worker.py`'s registry.** M5.1 owns that file; M5.2 exports callables.
* **It does not re-implement ownership falsification.** `sync/seen._falsify_ownership` is shipped,
  gated twice, and named in §12's M4.11 criterion. Under decision 327 the delta poll writes none.
* **It does not relax `all_items`'s three bounds.** They raise rather than truncate because the
  falsifier depends on it; the delta read is an addition beside them.
* **It does not build `POST /events/playback`.** §7.3's external-playback seam is **M7's** by
  decision 290 (`spec:353`), even though it shares the namespace M5.1 routes.
* **It does not change the conflict rule or anything in §7.3.** Seen-state sync is M4.11's, shipped.
* **It does not add a per-user webhook.** One token, one endpoint, one server.

## 9. Risks and gotchas

**`_falsify_ownership` is the most destructive statement in the tree and it already says so.** Its
docstring (`sync/seen.py:1123-1134`) records a gap review cycle 2 closed. Do not add a second caller,
do not relax either gate, and do not let the delta path near it.

**A `DateCreated` watermark initialised to epoch enqueues the whole corpus on first poll.** Initialise
it to the install's own creation time, and make that a test.

**Jellyfin's `DateCreated` is the server's, not the file's.** A library re-scan can re-stamp items
the household has had for years. The queue's `(kind, key)` identity absorbs the duplicate enqueue,
but the *job* must then find the title already owned and exit at stage 1 rather than re-acquiring.
Assert that, or a re-scan bills the household for its whole library.

**The Webhook plugin's payload is operator-authored.** Anything the handler requires is a field the
operator can forget to include. Require two, tolerate the rest, and publish the template.

**`ITEM_TYPES = "Movie,Series"` excludes `Episode`,** so an episode's item id never appears in the
client's own reads. The webhook path is the only place an Episode id enters the app from this
direction, and it must resolve through `SeriesId` before anything else touches it.

**`ops/fake_jellyfin.py` is a refuser, not a mock.** Do not "fix" its deliberate rejections, and
make the new emitter capable of the same kinds of refusal.

**`test_route_inventory.py`'s `ANONYMOUS` frozenset is not a place to add a line quietly.** Each
entry carries its reason, the untested set may only shrink, and the size is pinned so an addition
cannot be a one-line edit.

**Integration tests skip silently without `TEST_DATABASE_URL`.** Bring Postgres up with
`docker compose -f docker-compose.yml -f ops/compose.dev.yml up -d db` — the overlay is never
auto-loaded, so pass both `-f`.

**WebAuthn binds passkeys to the origin.** If any of this work is exercised through e2e later, the
run is against `http://localhost:8080` and never `127.0.0.1:8080`.
