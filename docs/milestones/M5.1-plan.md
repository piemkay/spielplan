# M5.1 — the spine: the queue, the raw store, the polite fetcher, and the ten-stage driver

> **This is a proposal, not an amendment.** It does not change `docs/spielplan-spec_v2.1.md` and it
> takes no decisions. Decisions **321, 322, 323, 331** and **332, 336, 340, 345** are recorded in
> [`ROADMAP-M5.md`](ROADMAP-M5.md#decisions-the-owner-must-take-numbered-from-321) and in section 3
> below; three of them gate this milestone's first commit and one of them gates its migration, which
> is checksummed the moment it is applied.

Nothing in §8 is buildable until work is durable, bytes are kept once, and the network is approached
politely. §8's own preamble names those three as **ported skeleton** — "the corpus project's raw
store (content-addressed, immutable — crawl once, re-parse forever), durable `(kind,key)` queue,
per-host rate-limited HTTP layer" (`docs/spielplan-spec_v2.1.md:359`) — and this app has none of
them. It also has two stages of §8 already built and waiting for a caller that does not exist:
`placement/reconcile.py:208-212`'s `app_acquired` scope has no caller anywhere in the tree, and
`home/shelves.py:1015-1053`'s "New in the library" shelf has no producer, because nothing ever
stamps `title.origin = 'acquired'`. This milestone is the machine between them.

It lands **first and alone**, and it holds `current_milestone`. That is M4.7's role in the previous
train, taken for the same reason: it owns the seams every other lane plugs into, and a lane that
opens before it has nothing to enqueue into.

---

## 1. Why these are one milestone

**The queue, the fetcher and the raw store are one decision made three times.** Every stage-2
fetcher writes bytes into the raw store, is rate-limited by host, and is driven by a task; every
stage-3 parse reads those bytes back. In the corpus these three are the narrow waist of the whole
import graph and nothing above them imports anything else:

```
mdc/http.py      -> config, db     (nothing else)
mdc/rawstore.py  -> config, db     (nothing else)
mdc/queue.py     -> db             (nothing else)
```

Split them and one of the three becomes a stub the other two are written against, which is a
contract nobody has read.

**The driver forces the seams.** §8's ten stages are a sequence with park-and-resume semantics
(`spec:398`: "Failure at any stage parks the job with a reason, retryable from admin"). Whoever
writes the driver decides what a stage *is* — a function of `(title_id, task) -> outcome`, what it
may write, how it reports — and every one of M5.2 through M5.5 implements against that shape. It
cannot be discovered later; it has to be published before the lanes open.

**`worker.py` and `app.py` are single-owner files by the file-locality test.** Every M5 job registers
in `worker.py`'s `JOBS` tuple (`:1008-1123`) and `Job("dna-projection", "M5", "acquisition", "<1 s")`
at `:1052` is already there with no `run` callable, waiting. Every M5 route lands behind either
`/api` or the new `/events` namespace, and `app.py:502-524`'s `SpaFallback` decides which paths the
SPA declines. Two agents editing either file in parallel is exactly the merge surface
`test_spec_coverage.py:275-278` names.

**And the scalar.** `spec_coverage.toml` carries one global `current_milestone` (`:20`, presently
`"M4.16"`). Only the milestone holding it has a red gate. Adding `"M5.1"`…`"M5.7"` to
`test_spec_coverage.py:285-286`'s `MILESTONES` and at least one M5.1 row must be **one commit**, or
the build is red for everyone — the M4.6 rule, stated at `ROADMAP-to-M5.md:60-62`.

**Depends on:** nothing. **Parallel with:** nothing.

## 2. What does not exist today

Every line reference is against `0b71b10` in the worktree, verified by reading the file.

### 2.1 There is no raw store, and the bundle does not ship one

`grep -rn "raw_document\|rawstore" backend/migrations/ backend/spielplan/` returns **nothing**. The
only hit anywhere in the tree is an unrelated column in a test fixture's SQL
(`backend/tests/fixtures/make_bundle.py:551`).

The corpus's is `mdc/rawstore.py` (170 lines) over `mdc/db.py`'s `raw_document` table. Its docstring
is the requirement (`mdc/rawstore.py:1-11`):

> "Every byte that came off the network is written here once, gzipped, named by the SHA-256 of its
> content, and never touched again. `raw_document` rows point at those files. Two fetches that
> return identical bytes share one file but get two rows, so the fetch history stays visible without
> duplicating bulk. This is the layer the whole project exists to protect: parsers, filters and
> schemas are all expected to change, and none of those changes may require another crawl."

**The mount already exists.** `docker-compose.yml:45` is `- ./data/raw:/data/raw` under
`x-worker-volumes` (`:44`), and the backend's anchor at `:57` deliberately omits it with the reason
at `:53-56`: *"nothing in the backend reads /data/backups or /data/raw at all, and a file that is
not in the container cannot be served out of it. [M4.7 sec-08]"*. The list is pinned as a static
guard at `test_static_contracts.py:1118`. So M5.1 does not create the mount; it becomes its first
user, and it must not move it. That is **decision 345**: §6.6's board is served by the *backend* and
cannot open a file the backend does not have.

**And the bundle does not supply a head start.** `data/export_bundle/v20260828/` contains exactly
`BUNDLE.json`, `artifacts/`, `content.sqlite` and `reviews.sqlite` — no `data/raw/`. §8's "All
fetched bytes land in the app's own raw store, so re-parsing is free forever" (`spec:398`) is a
promise about bytes M5 fetches *from M5 onward*.

### 2.2 There is no durable `(kind,key)` queue; `job_run` is an outcome log

`worker.py`'s `Job` registry (`:1008-1123`) is a cron of named callables. `job_run`
(`0017_ops.sql`) records per-job outcomes: `id, name, started_at, finished_at, ok, detail jsonb`.
There is no `(kind,key)` identity, no `UNIQUE`, no attempts counter, no `next_attempt_at`, no lease
owner, no priority, and no `paid` flag.

The corpus's is `mdc/queue.py` (257 lines): `UNIQUE(kind,key)`, states
`pending|leased|done|failed|skipped`, `LEASE_SECONDS = 900`, and `enqueue / enqueue_many /
reclaim_expired / lease / complete / skip / fail / defer / retry_failed / stats`. Its docstring is
the design constraint (`mdc/queue.py:1-8`): *"recovered by lease expiry, not by any shutdown handler
— which is the only way that actually survives `kill -9`"* and *"Task identity is `(kind, key)`.
Enqueueing the same pair twice is a no-op."*

**One worked example of a queue already exists in this tree and is the pattern to reuse, not the
machinery.** M4.14 put the bundle import off the request path by treating one `job_run` row as a
one-deep queue: `_claim_bundle_import` (`worker.py:713-745`) is
`UPDATE … WHERE id = (SELECT … FOR UPDATE SKIP LOCKED)` stamping `claimed_at` into `detail`;
`_finish_bundle_import` (`:773`) is one writer for all three exits; `_reap_abandoned_import`
(`:797`) closes a claim no process will finish, bounded by `BUNDLE_IMPORT_TIMEOUT = 600.0` (`:711`).
The claim/reap/one-writer idiom is worked out against a real failure and should be ported verbatim
into the new table. The *shape* cannot be: that is one job for one row at a time under an
install-wide lock, and M5 needs many concurrent per-title tasks across ten stages.

**`worker.py`'s loop is sequential and single-process.** `TICK_SECONDS = 20` (`:1148`), one tick, no
per-kind pool, no leasing. §5.3's own budget arithmetic (`worker.py:987-1006`) states the constraint
this milestone must respect: every `timeout` is at or under that job's interval because the loop is
sequential, with the bundle import as the single documented exception. An acquisition drain job is
the second, and it needs the same paragraph of argument.

### 2.3 There is no HTTP layer with any politeness at all

The app's only outbound HTTP is `JellyfinClient._request` (`connectors/jellyfin.py:201-231`) — a
bare `httpx.AsyncClient` per call, no retry, no backoff, no rate limit, no circuit breaker, no
conditional requests. `push/send.py` is its own one-shot delivery.

The corpus's is `mdc/http.py` (404 lines): per-host token bucket, concurrency caps, circuit breaker,
robots.txt cached in the DB, ETag/Last-Modified conditional requests, and `Retry-After`-honouring
exponential backoff with jitter. `mdc/config.py`'s `HOST_POLICIES` carries nineteen named hosts with
measured rps/burst/concurrency, including the deliberately-slow HTML connectors and a documented
robots override with its reasoning, plus a Jellyfin special case (the household's own server is not
a third party to be polite to).

**The spec never mentions robots.txt or a User-Agent**, and stage 2 names two scraped sources
(`rt:page`, `metacritic:page->reviews`, `spec:368`). That is **decision 340**: not a defect to fix,
a clause to add so the behaviour is falsifiable.

### 2.4 `acquisition_job` cannot hold a queue, and it already has rows

`0005_ledger.sql:133-142`:

```sql
CREATE TABLE acquisition_job (
    title_id   integer PRIMARY KEY REFERENCES title(id) ON DELETE CASCADE,
    stage      smallint NOT NULL CHECK (stage BETWEEN 1 AND 10),
    status     text NOT NULL CHECK (status IN ('queued','running','parked','ready','failed')),
    detail     jsonb NOT NULL DEFAULT '{}'::jsonb,
    reason     text,                       -- shown verbatim on the admin board
    retry_after timestamptz,               -- §8 stage 4: 30-day review-accrual window
    updated_at timestamptz NOT NULL DEFAULT now()
);
```

Three facts, all load-bearing for **decision 322**:

1. **`title_id` is the PRIMARY KEY.** One job per title, ever. No attempt history, no per-stage row,
   no re-run record; a retry overwrites. Stage 6's "never auto-retries past the spend cap" and stage
   4's 30-day window both need a history this shape cannot hold, and §8.4's flywheel needs to
   re-extract titles already at stage 10.
2. **The FK means a job cannot exist before its title row does**, while stage 1's job is what mints
   the title. `connectors/resolve.py:182-188` states the boundary: *"An unresolved item is
   *reported*, never invented … Acquiring genuinely new titles is §8's pipeline, which arrives at
   M5."*
3. **It is already populated by a different producer.** `placement/reconcile.py:368-403`
   (`_park_thin`) inserts at `PARK_STAGE = 2`, `PARK_STATUS = "parked"` (`:61-62`) with
   `ON CONFLICT (title_id) DO NOTHING` (`:249-253`) and a reason built from the block bookkeeping.
   §5.3 promises exactly this: thin titles "are still placed, badged, and parked as acquisition jobs
   for M5 enrichment". **M5's pipeline inherits those rows and must consume them rather than trip
   over them.** The count on the real 19,071-title install was not measured for this plan; count it
   before sizing stage 2 (see ROADMAP-M5.md's unknowns, item 2).

`retry_after` is present and read by nothing (`grep -rn retry_after backend/spielplan/` is empty).

### 2.5 `parked` already means something non-failing, and `failed` is unclaimed

The CHECK admits both `'parked'` and `'failed'`; §8 names only "parks". And `parked` already means
"placed successfully, needs enrichment" in the shipped tree — `reconcile.py:370-375` says it in as
many words: *"The title is ready — placed, badged, visible. It is the *job* that is parked, at §8
stage 2 (enrich)."* So the board cannot currently distinguish "enriched me, I'm fine" from "stage 6
blew up". **Decision 336.**

### 2.6 Stages 9 and 10 are built and have no caller

- **Stage 9.** `placement/reconcile.py:57` — `SCOPES = ("owned_missing", "app_acquired", "reimport",
  "all_missing")`; `:208-212` is the `app_acquired` branch, `SELECT id FROM title WHERE origin =
  'acquired' ORDER BY id`; `:442-446` skips warm classification for that scope.
  `grep -rn app_acquired backend/ frontend/ ops/` finds **four hits, all inside
  `reconcile.py` itself** — no caller. `place_titles` (`:256-365`) runs stages 9 and 10 in chunks of
  `CHUNK = 512`, upserts `title_placement` and stamps `title.placement = 'cold_tower'`,
  `placement_bundle`, `placement_at`.
- **`title.origin`.** `0008_placement.sql:46-48`, `CHECK (origin IN ('bundle','acquired'))`, partial
  index `title_acquired`, and the comment: *"The importer stamps 'bundle'; §8 stage 1 will stamp
  'acquired' at M5."* Nothing writes `'acquired'` today.
- **Stage 10.** `home/shelves.py:1015-1053`'s `new_in_library` shelf has predicate
  `t.placement = 'cold_tower'` and `why = "placed by the Cold Tower — no crowd data yet"`, and the
  badge fields are computed outside `model` on purpose (`shelves.py:474-484`) so §6.7's gating
  cannot make them vanish. `acquisition_job.status` already admits `'ready'`.

M5.1 supplies the producer. It builds no part of stage 9 or 10.

### 2.7 The id partition is in place and unused

`0015_seed.sql:24-25` — `title_id_seq` and `person_id_seq`, `AS integer MINVALUE 1000000000 START
1000000000 NO CYCLE`, set as the column DEFAULT, `OWNED BY` the columns, deliberately *not*
positioned by the migration. `importer/bundle.py` positions them at import. The comment at
`0015_seed.sql:39-44` names the beneficiary: *"this is the backstop for every other write path,
including §8 stage 1."* So `INSERT INTO title (kind, name, …)` with no id already mints correctly
into the app's half — M5.1 does not need new sequence work, only to not defeat it.

### 2.8 `/events` is not a namespace, and a POST to it answers 405

`app.py:502-524` — `SpaFallback.matches` returns `Match.NONE` only when
`path == "api" or path.startswith("api/")` (`:522`), and the fallback is registered
`methods=["GET"]` (`:545`). So a `GET /events/jellyfin` on a built container serves `index.html`,
and a **POST** to any unrouted `/events/...` path is a *partial* match, which Starlette answers with
**405** rather than 404 — the exact failure
`test_api_gating.py::test_the_spa_fallback_does_not_answer_for_the_api_namespace` was written to
catch for `/api`. §7.3 (`spec:353`, `POST /events/playback`) and §11 (`spec:438`) both also put
routes under `/events`, so this is a namespace, not one route. **Decision 332.**

### 2.9 Three guards will move under this milestone, and each is single-owner

- `test_layering_guards.py:421-434` — `ALLOWED_RESIDUE`, a per-module raw-SQL statement count for
  every file under `api/` plus `app.py`, `RESIDUE_TOTAL = 60`, enforced in **both** directions
  (grown and stale). `admin.py: 17` is the largest entry; `artifacts.py: 6` is the precedent M4.14
  set by giving its admin routes their own module rather than growing `admin.py`. Every M5 router
  follows that precedent.
- `test_layering_guards.py:553` — no domain package may import from `spielplan.api`.
- `test_route_inventory.py:75-98` — the `ANONYMOUS` frozenset, nine entries, each with its reason.
  `POST /events/jellyfin` is token-authed rather than session-authed, so it must be added here with
  its reason, and the "untested set may only shrink" ratchet means it arrives with a test naming it.

## 3. Owner decisions this milestone cannot take alone

Four, and each blocks a specific step. Record the answers as numbered entries in
`docs/spec-v2.2-proposals.md` before writing the code — a comment citing "the plan" points at
nothing.

**Decision 322 — is the queue `acquisition_job` or a new table? — gates `0024` and cannot be
revised.** Full argument in [`ROADMAP-M5.md`](ROADMAP-M5.md#decisions-the-owner-must-take-numbered-from-321)
entry 322; the evidence is §2.4 above. Recommended: keep the board, add `acquisition_task`.
**Migrations are sha256-checksummed the moment they are applied; this shape cannot be fixed later.**

**Decision 323 — does stage 1 mint from Jellyfin alone?** The fill-never-clobber resolver exists
(`resolve.py:112-179`) and refuses to mint. Recommended: mint only on a provider id; an item with
none parks at stage 1 with "no provider id". Evidence: `resolve.py:145-179`'s measurement — 2,438
titles share `(kind, lower(name))`, 573 groups still collide with the year applied.

**Decision 332 — where does `/events/jellyfin`'s token live, what does the route answer to a bad
one, and how is `/events` routed past the SPA fallback?** Evidence in §2.8. Recommended shape: the
token is a `connector_config` secret under `jellyfin`, generated at first save and displayed once
in §6.6's Jellyfin card; a wrong token is 401; a `SECRETS_KEY` failure is 503 naming
`SECRETS_UNREADABLE_REASON`; and `SpaFallback.matches` declines `events` exactly as it declines
`api`, in a one-line change, with the existing gating test **extended rather than duplicated**.
M5.1 makes the routing change and mounts `api/events.py` empty; M5.2 fills it.

**Decision 336 — what distinguishes `parked` from `failed`?** Evidence in §2.5. Recommended:
`parked` means "waiting on something that may change" (the 30-day window, the spend cap, thin-block
enrichment) and never auto-fails; `failed` means "this stage raised and will raise again" and is the
only state offering a plain retry; `reason` is verbatim on both. Proposal 109's three actions
(retry stage / retry from stage N / abandon) are adopted or struck by number under **decision 330**.

**Also relevant, and takeable later:** **340** (robots.txt and User-Agent in §8) and **345** (how
the board shows a raw document without re-mounting `/data/raw` on the backend). 345's recommended
answer is "it does not": the board links to the `raw_document` metadata row — url, status, sha256,
byte size, fetched_at, all in Postgres — and the bytes are reachable only by an operator on the box.
M4.7's sec-08 stands and `test_static_contracts.py:1118` pins it.

## 4. The work, in order

Phase 0 opens the milestone. Phases A-C are the three ported layers and touch nothing outside
`backend/spielplan/acquire/`. Phase D is the driver. Phase E wires the two built stages. Phase F is
the routing and the guards, and it lands **last**, because it is the only phase that edits `app.py`
and the inventory tests.

### Phase 0 — open the milestone, in one commit

**0a.** Insert `"M5.1"`, `"M5.2"`, `"M5.3"`, `"M5.4"`, `"M5.5"`, `"M5.6"`, `"M5.7"` into
`test_spec_coverage.py:285-286`'s `MILESTONES`, between `"M4.16"` and `"M5"`, with a comment saying
the list is **positional** and why (the same comment M4.6 added, for the same reason). Set
`current_milestone = "M5.1"` in `spec_coverage.toml:20`. Add at least one M5.1 row (§6 below).
**One commit.** Then run
`backend/.venv/Scripts/python -m pytest backend/tests/test_spec_coverage.py -q` and read the
failure: that list is the test plan.

**0b.** Re-point the eleven existing `milestone = "M5"` rows at the sub-milestone that owns each
(the mapping is in §6). Leave `jellyfin-acquisition-eval-spend-cap-meters-billed-tokens` and
`jellyfin-acquisition-eval-flywheel-enqueues-naming-failures` citing their bare proposals **until
decision 330 is taken** — then repair both `spec` strings in the same commit as the decision entry.
Do not rename `proposals` to `decisions`: `_laundered_decision_citations`
(`test_spec_coverage.py:1116-1126`) exists to catch exactly that repair.

**0c.** Spec amendments this milestone owns, if the owner takes them: §12's M5 row (decision 331),
§8's stage-1 mint clause (323), §8's fetcher politeness clause (340), §7.2's ownership bullet (327,
on M5.2's behalf — but M5.1 holds the file). **No other milestone edits the spec.**

### Phase A — the raw store

**A1. `acquire/rawstore.py`**, ported from `mdc/rawstore.py`. Gzip, SHA-256 content addressing under
`/data/raw/<source>/<kind>/`, write-once. The two-fetches-one-file-two-rows rule is the invariant
and the test.

**A2. `raw_document` in `0024`**, ported from `mdc/db.py`'s shape: `source, kind, entity_key, url,
http_status, fetched_at, content_sha256, content_path, content_type, byte_size, page, request_meta,
ok, error, run_id`. Index at least `(source, kind, entity_key)` and `(content_sha256)`.

**A3. The custody boundary, stated where it is enforced.** A comment in `rawstore.py` citing
`docker-compose.yml:53-56` and decision 181 (M4.7 sec-08): the worker writes here, the backend
cannot read it, and §6.6's board reads the row rather than the bytes. Do **not** touch
`x-backend-volumes` or `test_static_contracts.py:1118`.

### Phase B — the polite fetcher

**B1. `acquire/fetch.py`**, ported from `mdc/http.py`: `TokenBucket`, per-host concurrency cap,
circuit breaker with a cooldown, conditional requests (ETag/Last-Modified off the previous
`raw_document` row), `RETRYABLE_STATUS`, exponential backoff with jitter, `Retry-After` honoured with
`max(retry_after, backoff*3)` on a 429. Typed failures: `FetchError`, `HostPaused`,
`RobotsDisallowed(retryable=False)`.

**B2. `acquire/hosts.py`** — `HOST_POLICIES` as data, ported from `mdc/config.py`, with the measured
rps/burst/concurrency per host and the two deliberately-slow HTML connectors kept slow. Read as
config rather than as constants, so §6.6 can show it; do not build an editor here (that is M5.7's
territory and probably not in scope at all).

**B3. robots.txt cached in Postgres**, in `0024`, and a declared User-Agent naming the app — **only
if decision 340 says §8 requires it.** If the decision is not taken, port the behaviour and open the
question in the module docstring rather than inventing a spec clause.

**B4. The Jellyfin exception.** The household's own server is not a third party; `HOST_POLICIES` must
not throttle it, and `connectors/jellyfin.py` stays on its own client. **Do not rewrite the Jellyfin
client onto this fetcher** — it is M5.2's file and a shipped, hardened one.

### Phase C — the durable queue

**C1. `acquisition_task` in `0024`** — the shape decision 322 chooses. If the recommendation is
taken: `(kind, key)` UNIQUE, `payload jsonb`, `priority`, `state`, `attempts`, `max_attempts`,
`next_attempt_at`, `lease_owner`, `lease_expires`, `last_error`, `result_note`, `paid boolean`,
`created_at`, `updated_at`. The `paid` flag is not decoration: `mdc/sources/base.py:51-53` carries
it because *"at corpus scale the difference between them is roughly a hundred euros a click"*.

**C2. `acquire/queue.py`** — `enqueue`, `enqueue_many`, `lease`, `complete`, `fail`, `skip`,
`defer`, `reclaim_expired`, `stats`. `lease` uses the `FOR UPDATE SKIP LOCKED` claim already worked
out at `worker.py:736-745`; `reclaim_expired` is the reaper, in the shape of
`_reap_abandoned_import` (`worker.py:797-861`) and bounded by the same argument. **Lease expiry, not
a shutdown handler** — `mdc/queue.py:1-8` explains why, and a `kill -9` test is the proof.

**C3. `defer(kind, key, until)`** exists for stage 4's 30-day window and is the only mechanism for
it. Do not put the window in `acquisition_job.retry_after` alone; that column is the board's copy of
the fact, not its schedule.

**C4. The drain job.** A `Job("acquisition-drain", "M5.1", "queue", …)` in `worker.py`'s `JOBS`
with a `run` that leases and executes a bounded number of tasks per tick. Its `timeout` must respect
§5.3's rule that the loop is sequential (`worker.py:987-1006`) — write the same paragraph of
argument the bundle-import entry carries, or the budget guard is a lie.

### Phase D — the ten-stage driver

**D1. `acquire/pipeline.py`** — one `STAGES` tuple carrying §8's ten names **verbatim and in order**
(`identify · enrich · derive · reviews gate · dna pack · dna extract · verify · project · place ·
ready`), each with a callable and a `paid` flag. Proposal 136 (`spec-v2.2-proposals.md:1617`) argues
the board's labels should be these strings verbatim; whether that clause is adopted is decision
330's business, but the *code* should carry one tuple either way so there is one spelling.

**D2. Park-and-resume.** A stage returns advance / park(reason, until=None) / fail(reason). Park
writes `acquisition_job.stage`, `.status`, `.reason` verbatim and, for stage 4, `.retry_after`; the
task is `defer`red or left `pending` accordingly. **Resume re-enters at the parked stage**, which is
what coverage row `...stage-park-retry-idempotent` asserts, and re-reads the raw store rather than
re-fetching.

**D3. Stages 2-8 ship as declared no-ops.** Each is a callable that advances and records "not
implemented at M5.1 — owned by M5.<n>" in `detail`. This is what makes the spine testable end to
end before any lane opens, and it is the reason M5.1's exit criterion is runnable at all. Say so in
each stub's docstring with the owning milestone, so a stub that survives into M5.6 is visible.

**D4. Stage 1 — `identify`.** Resolve through `connectors/resolve.resolve_title_id` first
(fill-never-clobber, already shipped); on no match, mint per **decision 323**. A minted row is
`INSERT INTO title (kind, name, year, …)` with **no id**, so `title_id_seq`'s DEFAULT applies
(`0015_seed.sql:27`), and `origin = 'acquired'` (`0008_placement.sql:46-48`). Then insert the
`acquisition_job` board row.

**D5. Idempotence is a property of every stage, tested once.** Running the same task twice must
produce the same rows. This is §14 risk 5's invariant applied to the driver rather than to the
derive, and it is cheap to hold here and expensive to retrofit.

### Phase E — wire the two stages that already exist

**E1. Stage 9 — `place`.** Call `placement.reconcile` with `scope="app_acquired"`
(`reconcile.py:208-212`), which has no caller today. Two integration details: `title_placement.
bundle_version` is `NOT NULL REFERENCES artifact_bundle(version)` (`0008_placement.sql:14`), so an
acquired title **cannot be placed on an install with no active bundle** and §3.1 makes that a legal
state — the stage must park with that reason rather than raise. And `_park_thin` (`:368-403`) is
already a writer of `acquisition_job`; reconcile its `ON CONFLICT DO NOTHING` with the pipeline's

## 9. Risks and gotchas

**`0024` is checksummed the moment it is applied, and decision 322 is inside it.** If the queue's
shape is wrong, the repair is a second migration that copies and drops — on a table the flywheel and
the board both read. Get 322 answered before Phase C, and if it has been applied on a dev box and
must change, **drop the scratch database rather than editing the file**.

**`acquisition_job` is not empty on a real install.** `placement/reconcile._park_thin` has been
writing `(stage=2, status='parked')` rows since M4.13's sweep. The pipeline must treat them as its
inbox, and `ON CONFLICT (title_id) DO NOTHING` (`reconcile.py:252`) means a nightly sweep can
silently do nothing to a title already in flight — which is the behaviour you want, but only if the
driver never relies on the sweep to advance anything.

**`title_placement.bundle_version` is `NOT NULL`** (`0008_placement.sql:14`) and §3.1 makes a
bundle-less install legal. An acquired title on such an install cannot be placed. Park, do not
raise.

**The `ALLOWED_RESIDUE` guard fails in both directions.** Adding a router without updating
`test_layering_guards.py:421-434` reddens the build; so does updating it and then moving the query
into a domain package. Update it in the same commit as the router, and update `RESIDUE_TOTAL` with
it.

**`test_route_inventory.py`'s untested set may only shrink.** Every new route arrives with a test
that names it. There is no one-line edit that silences this.

**`test_devstub_contract.py` compares the harness's route set to the app's.** A route added in F3
without a matching `ops/devstub.py` entry is a red build, and `devstub.py` is a harness rather than
the app — `backend/spielplan/api/` wins on any disagreement.

**Never run bare `pytest` from the repo root.** The config lives in `backend/pyproject.toml` with
`asyncio_mode=auto`; without the path argument the async tests error.
`backend/.venv/Scripts/python -m pytest backend/tests -q`.

**The corpus is read-only.** Port by reading and rewriting; never edit
`C:/Users/pmk/Workspace/movie_data_curator`, and never let a Spielplan requirement depend on a
change landing there.

**Line length is 108 on purpose** so spec sentences can be quoted inline. `ruff format` is not
enforced — do not reformat `worker.py`, `app.py` or `reconcile.py` wholesale while editing them;
those three are the densest argued files in the tree and a reformatted diff is an unreviewable one.

**Keep console and test output ASCII.** The exit script prints; a `·` or a `✓` crashes a Windows
cp1252 console, and `M4.14-plan.md:406-413` records that exact defect being fixed once already.
