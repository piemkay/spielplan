# M5.5 — the LLM connector layer: the validator is the guarantee, and the meter counts what is billed

> **This is a proposal, not an amendment.** Decisions **324, 325** and **337, 338, 343** are recorded
> in [`ROADMAP-M5.md`](ROADMAP-M5.md#decisions-the-owner-must-take-numbered-from-321). 324 and 325
> block this milestone's first commit and 325 gates its migration. Only **M5.1** edits the spec file.

§9 is six sentences and two of them are hard-won corrections that a straightforward implementation
gets wrong:

> "**The schema is a cost-saving device, not the guarantee — the guarantee is the validator**
> (ported principle). Two-attempt pattern: retry once with the specific contract violation named."
> (`docs/spielplan-spec_v2.1.md:412`)
>
> "…including the reasoning-token accounting corrections (Gemini bills thinking tokens as output —
> counting visible JSON understates cost ~5x)." (`spec:410`)

The first says a structured-output mode is an optimisation and the validator is the boundary — which
is why this milestone depends on M5.4 at *runtime* and imports nothing from it that M5.4 does not
export. The second says a meter that counts the JSON reports about a fifth of the truth, and the
coverage row says the same thing from the test side: *"a cap computed from the wrong number is not a
cap"* (`spec_coverage.toml:3213`).

This milestone is the three adapters, the two-attempt pattern, the consensus arithmetic, the spend
meter and the generic connector plumbing §6.6 needs. It ships **no UI**: the provider cards and the
spend guard are M5.7's.

---

## 1. Why these are one milestone

**Three adapters, one contract.** The coverage row is explicit: *"The behaviour is identical across
the Gemini, Anthropic and OpenAI adapters despite their different structured-output mechanisms"*
(`spec_coverage.toml:3239`). Three providers solving structured output three different ways
(forced tool-use, strict-schema stripping, `responseSchema`) can only be held to identical
enforcement by one milestone that writes all three.

**The meter and the adapters are one number.** Reasoning-token accounting is *inside* the Gemini
adapter — `tokens_out = candidatesTokenCount + thoughtsTokenCount` (`mdc/llm/client.py:301-303`) —
and the cap is a `SUM` over what the adapters report. Split them and the meter is a table with no
correct writer.

**The generic connector plumbing is the milestone's own opening work.** `ROADMAP-to-M5.md:578` files
it as DEFERRED-B and says why: *"The generic ConnectorSpec and the single title-write path exist to
serve writers M5 builds (acquisition, the LLM layer)."* M5.3 consumes it for tmdb/omdb/trakt; M5.5
writes it, because the three LLM providers are the family that has no automated-install path at all.

**Depends on:** M5.1 (the rate-limited fetcher every POST goes through) and M5.4 **at runtime** (the
validator the retry retries against). **Parallel with:** M5.2, M5.3. The M5.4 dependency is a
runtime one, not a file one — M5.5 can be written against `dna/verify.py`'s signature and integrated
when both land.

## 2. What does not exist today

### 2.1 There is no LLM anything in this app

`grep -rni "gemini\|anthropic\|openai" backend/spielplan/ backend/pyproject.toml` returns **nothing**.
No adapter, no key, no model, no task assignment, no spend table, no meter.

`connectors/__init__.py:1` says so: *"Outbound connectors. Spec v2.1 §7 (Jellyfin); TMDB/OMDb/Trakt/
LLM arrive with M5."*

### 2.2 The no-SDK constraint is currently satisfied by absence

§9: "Ported design (no vendor SDKs; one POST per provider through the rate-limited fetcher; batch
endpoints supported)" (`spec:408`). `backend/pyproject.toml:20-30` carries `webauthn`,
`python-multipart`, `httpx`, `numpy`, `torch` and `zstandard` — and no provider SDK.

So the constraint holds today because nobody has added one, and the moment this milestone opens it
becomes a thing somebody could reasonably add. **A static guard should keep it true**, in the shape
`test_static_contracts.py` already uses for the CPU-only torch index (`:1213`) and the one
plain-HTTP port (`:915`).

### 2.3 The one connector family M5 is about has no automated-install path

§2 says env vars may seed "Jellyfin, LLM, TMDB, OMDb, Trakt" (`spec:59`).
`connectors/registry.py:88-99`'s `env_seeds` seeds `jellyfin`, `tmdb`, `omdb` and `trakt`, with the
comment *"§6.6 configures these in the admin UI at M5; seeding them here means an automated install
can arrive with them already filled in"*. `core/config.py:69-74` declares
`jellyfin_url, jellyfin_api_key, tmdb_api_key, omdb_api_key, trakt_client_id, trakt_client_secret`
— **and no provider field at all**.
`test_static_contracts.py::test_compose_forwards_every_connector_seed_variable` (`:1041`) holds
compose forwarding exactly those six.

### 2.4 `registry.py` has `load_jellyfin` / `save_jellyfin` and nothing generic

`connectors/registry.py` carries `JellyfinConfig` (`:39-73`), `load_jellyfin` (`:233`),
`save_jellyfin` (`:245`), `make_client` (`:171-186`), `env_seeds` (`:76`) and `seed_from_env`.
There is no `load_connector(name)` / `save_connector(name, …)`, no `ConnectorSpec`, and no
per-connector test-button dispatch — `api/admin.py:156-233` and `:504-633` are Jellyfin-shaped
routes.

The storage layer underneath is already generic and already good: `connector_config`
(`0001_system.sql:22-30`) is `name text PRIMARY KEY, config jsonb, secrets_encrypted bytea,
secrets_key_id text` with a CHECK pairing the two secret columns, and `core/secrets.py` gives
`put_connector_secrets`, `put_connector_config`, `get_connector_secrets`, `seal`/`open_sealed`,
`aad_for(table,row)` and a typed `SecretsUnreadable`. `registry.py:203-213` does the sealed
read-modify-write under `FOR UPDATE` and argues why.

### 2.5 The header-only key matters here, and the app already has the machinery that would leak it

§9 names it: "Gemini responseSchema + **header-only API key so credentials never hit logs**"
(`spec:410`). The corpus's comment is more specific (`mdc/llm/client.py:273-276`): *"The key goes in
a header, never the query string — a URL with a credential in it ends up in logs, the http_cache
table and the raw store's `url` column."*

**All three of those exist in this app.** `push/send.py:92-107` already installs a logging filter
because *"`httpx` logs one INFO line per request with the full URL in it"*, and M5.1's
`raw_document` carries a `url` column. A Gemini key in a query parameter would be logged by
machinery this app already runs and stored in a table M5.1 just created. Port the header form
verbatim and do not "simplify" it.

### 2.6 There is no spend table, no cap, and no meter

`grep -rn "spend" backend/migrations/` matches one comment in `0004_dna.sql`. No `llm_call`, no
`spend_cap`, nothing.

§6.6's meter reads "$4.12 of $25.00 this month" (`spec:321`) — the $25.00 is an example inside a
caption, not a stated default — and §8 says "paid stages (6) never auto-retry past the spend cap"
(`spec:398`). Nothing says whether the month is a calendar month or a rolling thirty days, what
timezone bounds it, or where the rows live. **Decision 325.**

### 2.7 The consensus arithmetic is unstated in the spec and settled in the corpus

§6.6 gives the numbers — "union recalls 93% vs 67% for intersection; agreement is a weight, never a
filter" (`spec:321`) — and §4.1 rule 2 makes the constraint binding (`spec:99`). Neither states the
function from agreement count to `dna_tag.confidence`.

`mdc/dna/store.py:246-275` (`merge_passes`) states it exactly:

* `confidence = round(counts[term] / n_runs, 2)` — the share of runs that found the term;
* `runs_found = counts[term]`, which is the app's `n_sources`;
* salience is **the max any pass assigned**, with its own argument: *"a pass that saw a trait as core
  is better evidence than one that saw it as minor, and the confidence weight already records how
  alone it was in seeing it at all"*;
* evidence from every pass that found it is kept, not just the winner's.

It counts **passes**, and a pass is a (provider, pass-index) pair — so a two-pass single-provider
union and a two-provider union are the same arithmetic. That is **decision 337**'s recommended
answer, and it is portable verbatim.

`dna_tag`'s `UNIQUE (title_id, version, term, provider)` (`0004_dna.sql:86`) already encodes the
per-provider row, made functional by `0018` collapsing a NULL provider to `''`.

### 2.8 Two of §6.6's three task slots have no caller at M5

§6.6 asks for "a per-task model assignment (extraction / query parsing / conflict phrasing)"
(`spec:321`). "Query parsing" is §6.4's compositional search, which §12 puts at **M6**; "conflict
phrasing" is §6.2/§6.5 conflict copy, and `ROADMAP-to-M5.md:578` says it *"has no caller for the same
reason"*. Only extraction has a consumer in M5. **Decision 339**, owned by M5.7.

### 2.9 Batch mode's latency is incompatible with a board an operator reads

§9 says "batch endpoints supported" (`spec:408`) and §6.6 asks for a batch-vs-sync toggle. The corpus
has `mdc/llm/batch.py` (488 lines) and it carries the same reasoning-token correction
(`:440-441`). Batch endpoints have latency in hours. Nothing says what a batch-mode stage 6 does to a
job's stage timing, or whether "unattended" tolerates it, and §6.6's board shows a per-title stage.
**Decision 338.**

## 3. Owner decisions this milestone cannot take alone

**Decision 324 — parallel mode's default and the default pass count.** Blocks Phase D and the whole
cost surface. `spec_coverage.toml:3159` explicitly forbids a test asserting the default, so **no test
in this milestone may assert it until the decision lands**. Recommended: off, one pass — §6.6's own
"cost estimate before enabling" reads as an off default, and two providers at two passes is 4x the
bill.

**Decision 325 — the cap's period and default.** Gates migration `0028`'s shape. Recommended:
calendar month in the install's `TZ`, `llm_call` rows, meter as a `SUM`. The decision must also say
whether the two-attempt retry's second call is **budgeted inside** the cap or **checked against** it
— they differ by up to 100% on a violating title.

**Decision 337 — the agreement-to-confidence map.** Blocks Phase E. Recommended: port `merge_passes`
verbatim — `confidence = agreeing_runs / total_runs`, `n_sources = agreeing_runs`, salience = max,
written for every surviving tag including single-run ones (confidence 1.0 at `n_runs = 1`). Add a
static guard that no query in `backend/` filters on `confidence`; `test_landmine_guards.py:56-61`
already has the shape.

**Decision 338 — does batch mode ship at M5?** Recommended: **sync only at M5**. A job that sleeps
for hours is hard to reconcile with a board an operator reads, and §12's criterion says nothing about
latency. The toggle ships disabled with its reason, or §9's clause is narrowed. `mdc/llm/batch.py`
stays unported and is named in §8 below as deliberately out of scope.

**Decision 343 — where model prices live.** Jointly owned with M5.7, which renders the estimate.
Evidence: `mdc/config.py:151-153` records that the entire Gemini 2.5 family answers 404 for new keys,
and §6.6's published baseline (~$0.005-0.01/title/pass) reproduces only at 2.5-flash batch pricing —
so the spec's caption is three to six times low against the current default. And
`mdc/config.py:157-159`: gemini-3.7-flash's introductory pricing *"expires: from 2027-01-01 these
double to $1.50 / $7.50"*. Hard-coding puts a known-wrong number in the meter on a known date.
Recommended: prices ship as a table **with a `valid_until`**, the estimator refuses to guess for an
unknown model rather than inheriting a prefix's price (`mdc/config.py:190-200` explains why
`startswith` is the trap), and the admin can override.

## 4. The work, in order

### Phase A — the generic connector surface

**A1. `ConnectorSpec`** in `connectors/registry.py` — name, config schema, secret fields, a test
callable, and whether it is a seeding target. `load_connector(name)` / `save_connector(name, …)` over
the existing `connector_config` storage, using the sealed read-modify-write under `FOR UPDATE` that
`registry.py:203-213` already argues for.

**A2. `load_jellyfin` / `save_jellyfin` become the first two `ConnectorSpec` instances**, not a
parallel path. Their behaviour must not change: `JellyfinConfig`'s `api_key` is
`field(repr=False)` (`:170`), `secrets_unreadable` degrades rather than raising, and M5.2 may be
holding this file's *consumers* — coordinate before editing.

**A3. Env seeding for the three providers.** `core/config.py` gains
`gemini_api_key`, `anthropic_api_key`, `openai_api_key` (and model overrides if the owner wants
them), `env_seeds` gains the three entries, and `docker-compose.yml` forwards them —
`test_static_contracts.py:1041` will otherwise fail, by design, and that failure is the guard
working.

**A4. Per-connector test dispatch.** §6.6 gives every card a test button. One dispatch table, not a
route per provider; M5.7 renders the buttons.

### Phase B — the three adapters

**B1. `llm/client.py`** — the common shape ported from `mdc/llm/client.py`: `LLMResult` (provider,
model, payload, tokens_in, tokens_out, raw), `LLMError(retryable=...)`, `TIMEOUT_S`, one tool name,
and `_loads` with its markdown-fence tolerance. **Every POST goes through M5.1's fetcher**, so
retries, backoff and the breaker come from there rather than from three hand-rolled loops.

**B2. `llm/anthropic.py`** — forced tool-use. The response is read out of the `tool_use` block
(`mdc/llm/client.py:186-192`), and a forced tool call that comes back as prose is a named error
carrying `stop_reason`, retryable only when it is `max_tokens` (`:193-198`). Tokens from
`usage.input_tokens` / `usage.output_tokens`.

**B3. `llm/openai.py`** — strict schema with the unsupported keywords stripped.
`_STRICT_UNSUPPORTED = {"minItems","maxItems","minimum","maximum", …}` (`mdc/llm/client.py:102-105`)
and `_strip_keywords` (`:107`). Two details a port loses: `max_completion_tokens` rather than the
deprecated `max_tokens`, *"the reasoning-capable models reject the latter outright"* (`:222-223`);
and `message.refusal` is a non-retryable error distinct from empty content (`:239-247`).

**B4. `llm/gemini.py`** — `responseSchema` under `generationConfig`, `temperature: 0`,
`responseMimeType: application/json`, and **the key in an `x-goog-api-key` header**
(`mdc/llm/client.py:273-278`). No candidates is a non-retryable error naming `promptFeedback.
blockReason`; an empty candidate is retryable only on `finishReason == "MAX_TOKENS"`.

**B5. Reasoning-token accounting, in the Gemini adapter, with its measurement in the comment.**
`tokens_out = candidatesTokenCount + thoughtsTokenCount` (`mdc/llm/client.py:301-303`), and the
comment records *"measured at 59% of billable output missing on this prompt, because the answer is
short and the reasoning is not. OpenAI folds its reasoning tokens into `completion_tokens` already;
Gemini does not."* Port the sentence; it is the argument for the line.

**B6. The no-SDK static guard.** A test that reads `backend/pyproject.toml` and fails on a provider
SDK, in the shape of the CPU-only torch guard (`test_static_contracts.py:1213`), citing §9.

### Phase C — the contract and the two-attempt pattern

**C1. `llm/contract.py`** — the extraction request's JSON schema, per provider mechanism, built from
one definition so the three adapters cannot diverge in what they ask for.

**C2. The two-attempt loop.** Call, validate through **M5.4's `verify_payload`**, and on a contract
violation retry **exactly once** with the specific violation named in the retry prompt. A second
violation fails the stage and writes nothing. The coverage row is precise about all three clauses
(`spec_coverage.toml:3238-3239`).

**C3. Attempt 2 is a paid call and the meter must see it.** Whatever decision 325 rules about
budgeting, both attempts are metered.

**C4. The retry prompt names the violation, not "try again".** `unknown_term: 'themes.mecha' is not
in vocabulary v1` is actionable; a generic retry is a second full input pass for nothing.

### Phase D — spend

**D1. `llm/pricing.py`** — the price table per decision 343, ported from `mdc/config.py:134-163`,
**with `price_for`'s boundary rule** (`:190-200`): a prefix matches only at a name boundary, so
`gpt-5.6-terra` does not inherit `gpt-5`'s price, and an unknown model returns `None` rather than a
confident wrong number. The corpus's comment says why: *"A bare `startswith` looks harmless and is
how a cost estimate quietly invents a number."*

**D2. `llm/spend.py`** — write an `llm_call` row per attempt, and `remaining(cap)` as a `SUM` over
the period decision 325 chooses. A `SUM` rather than a counter, because a counter can drift and a
drifted cap is not a cap.

**D3. Stage 6 checks the cap before issuing a paid call and parks `over spend cap` when it would
breach.** Not after; not as a warning. And **never auto-retries** past it (`spec:398`) — the task is
parked, not deferred with a backoff.

**D4. The per-title estimate** as a domain function M5.7 calls: tokens in x price in + `MEAN_OUTPUT_
TOKENS` x price out, multiplied by passes and by providers. Export it; do not render it.

### Phase E — consensus

**E1. `merge_passes`** ported per decision 337: union, `confidence = agreeing_runs / total_runs`,
`n_sources = agreeing_runs`, salience = max across passes, evidence kept from every pass that found
the term.

**E2. Write per-provider rows.** `dna_tag`'s `UNIQUE (title_id, version, term, provider)` is the
parallel-mode key and it exists for this.

**E3. Agreement is a weight, never a filter.** §4.1 rule 2, and a static guard in the shape of
`test_landmine_guards.py:56-61`. A single-run tag gets confidence 1.0 and is written like any other.

**E4. The 93%/67% numbers are about providers.** §6.6 ships them as the toggle's caption. If the
port counts runs rather than providers (recommended), label the caption's numbers as measured over
providers rather than asserting them for passes.

### Phase F — the refusing double

**F1. `ops/fake_llm.py`** — a **refuser**, not a mock, in the spirit of `ops/fake_jellyfin.py`
rejecting the admin key on the Played write on purpose. It returns:

* a schema-valid response containing a **fabricated tag**, on purpose — the case §8 stage 7 exists
  for and the case the two-attempt retry is written against;
* a schema-valid response containing an **unquotable evidence string**;
* a response with a salience outside {1,2,3};
* a refusal (OpenAI's `message.refusal`), a `max_tokens` cut-off, and a prose answer where a
  `tool_use` block was forced;
* usage blocks with and without `thoughtsTokenCount`, so the meter's arithmetic is exercised on both.

**F2. Three provider shapes, one double.** The response envelopes differ; the double must speak all
three or "identical across three adapters" is untested.

## 7. Exit criterion, as something to run

> Against a refusing double speaking all three providers' envelopes: a response that satisfies the
> request schema but violates the extraction contract — a term the vocabulary does not carry, or an
> evidence string that is not in the pack — is rejected by the validator and retried **exactly
> once**, with the specific violation named in the retry prompt; a second violation fails the stage
> and writes nothing. The behaviour is identical across the Gemini, Anthropic and OpenAI adapters
> despite three different structured-output mechanisms. The meter charges billed output tokens
> including thinking tokens, so a Gemini call reporting 1,600 candidate tokens and 2,300 thought
> tokens is metered at 3,900. With the running period at the cap, a job reaching stage 6 parks
> `over spend cap` **without issuing a paid call**, never auto-retries, and an admin retry that
> would breach the cap is refused with that reason. No provider key appears in any URL, any log line
> or any `raw_document.url`.

| # | measure | pass |
|---|---|---|
| 1 | schema-valid, contract-violating response | rejected; exactly one retry |
| 2 | retry prompt | contains the violated rule and the offending value |
| 3 | second violation | stage fails; `SELECT count(*) FROM dna_tag WHERE title_id = …` unchanged |
| 4 | the same three cases on all three adapters | identical outcomes |
| 5 | Gemini usage 1,600 + 2,300 | `llm_call.tokens_out_billed` = 3,900 |
| 6 | OpenAI usage | `completion_tokens` used as-is (it already folds reasoning) |
| 7 | meter at the cap, job reaches stage 6 | parked `over spend cap`; zero outbound provider requests |
| 8 | the same job on the next tick | still parked; no auto-retry |
| 9 | admin retry over the cap | refused with that reason; nothing queued |
| 10 | `grep` every URL built by `llm/` | no key |
| 11 | `raw_document.url` for a provider call | no key |
| 12 | the httpx INFO line for a provider call | no key |
| 13 | `price_for("openai", "gpt-5.6-terra")` | the terra price, **not** `gpt-5`'s |
| 14 | `price_for` for an unknown model | `None`, and the estimator says "unknown" rather than a number |

## 8. What this milestone deliberately does NOT do

* **It does not build the verifier.** §8 stage 7 is **M5.4's**, and the separation is §9's own
  principle expressed as a module boundary: the corpus's verifier does not import its LLM client and
  neither does this one in reverse. This milestone *calls* the validator.
* **It does not build the pack.** Stage 5 is **M5.4's**.
* **It does not build any UI.** Provider cards, the per-task assignment control, the batch/sync
  toggle, the cap input and the meter are **M5.7's**. This milestone ships APIs and a domain
  estimate function.
* **It does not build the flywheel or its cost estimate surface.** §8.4 is **M5.6's**; the per-title
  estimate is exported for both.
* **It does not port `mdc/llm/batch.py`** (488 lines), per decision 338's recommendation. Batch
  endpoints have hour-scale latency and §6.6's board shows a per-title stage. If the owner rules the
  other way, batch is its own step and its own coverage row, and the board needs a state for
  "waiting on a batch".
* **It does not build the "query parsing" or "conflict phrasing" task slots.** Neither has a caller
  before M6/M7 (`ROADMAP-to-M5.md:578`), and a settings control for a task nothing calls is a promise
  the surface cannot keep. **Decision 339**, M5.7's.
* **It does not touch `worker.py`.** M5.1 registers jobs.
* **It does not add an LLM call anywhere outside stage 6.** One consumer at M5.
* **It does not set a default cap or a default mode on its own.** Decisions 324 and 325.

## 9. Risks and gotchas

**The structured-output mode is not the guarantee, and it is very easy to act as though it is.** A
schema-conforming response containing a fabricated term is the normal case this milestone exists to
handle. Every adapter test must include one, and the refusing double must produce one by default
rather than on request.

**Gemini's thinking tokens are roughly half the billed output** and they never appear in the
response. `mdc/config.py:181-185` measures gemini-3.6-flash at ~1.6k output plus ~2.3k thoughts. A
meter that counts the JSON reports about a fifth of the truth.

**`price_for`'s prefix matching is a trap with a comment on it.** `gpt-5.6-terra` must not inherit
`gpt-5`'s price. Port the boundary rule and the `None` return; an estimator that invents a number is
worse than one that says it does not know.

**The Gemini price expires on 2027-01-01** and doubles (`mdc/config.py:157-159`). Whatever decision
343 rules, the table needs a date beside the number.

**The whole Gemini 2.5 family answers 404 for new keys** (`mdc/config.py:151-153`), which is the
family §6.6's published baseline was measured on. A first-run estimator seeded from the spec's
caption is three to six times low.

**A key in a query string is logged by machinery this app already runs.** `push/send.py:92-107` had
to install a filter for exactly this, and M5.1's `raw_document.url` is a second place it would land.

**`test_static_contracts.py::test_compose_forwards_every_connector_seed_variable` fails the moment
you add a config field without forwarding it.** That is the guard working.

**`spec_coverage.toml:3159` forbids a test on parallel mode's default.** Do not add one to close a
red row; take decision 324 instead.

**Two M5 coverage rows cite bare proposals and one of them is this milestone's.** Decision 330 is the
only repair; `_laundered_decision_citations` (`test_spec_coverage.py:1116-1126`) exists because
renaming the word is the cheap way out and somebody will try it.

**Integration tests skip silently without `TEST_DATABASE_URL`.** The meter and the cap live there.

**Line length 108, ASCII in console output.** The exit script prints a cost table; keep the currency
plain.
