# M4.15 — the shell on a phone: the chrome every surface sits inside

**This milestone is not in §12.** It exists because §6's preamble — "responsive PWA, phone-first
(48 px targets, one-handed, swipe), desktop as progressive enhancement, installable,
service-worker shell cache" — is normative and has never had an owner. Every surface milestone
shipped its own screen correctly and left the box around it alone, so the box now contains: a
header the iPhone status bar covers, a tab bar iOS Safari's toolbar hides, thirty form controls
that zoom on focus and do not zoom back, menus that cannot be dismissed, one accent spent on six
meanings, the prose register set in the data face, and a fetch wrapper that has no timeout, no
401 branch and no idea what a pydantic 422 looks like. Twenty-nine findings, six files, one
milestone.

It runs **last** among the pre-release frontend milestones and it carries **no release blocker**.
That is deliberate: the surfaces have to stop moving before they are reskinned.

---

## Why these changes are one milestone

Six files carry all twenty-nine findings:

| file | what it owns here |
|---|---|
| `frontend/src/app.html` | the viewport meta and the iOS status-bar style |
| `frontend/src/routes/+layout.svelte` | shell height, header inset, logout, the boot/offline state |
| `frontend/src/lib/design.css` | the two type voices, the ink tokens, the coarse-pointer rules, `--touch` |
| `frontend/src/lib/api.js` | the deadline, the error shape, the 401/403 seam |
| `frontend/src/lib/session.svelte.js` | what a failed boot means |
| `frontend/src/lib/components/NavRail.svelte` | the bottom bar and its safe-area padding |

They are exactly the files every other frontend milestone must be **forbidden** from editing.
Split this work across milestones and the safe-area rule, the 48 px token and the 401 branch get
three incompatible versions — which is how the tree arrived at a coarse-pointer block that sets
`min-height` and never `min-width`, and at nine components that each solved their own focus ring.

Every finding here is a **rule that has to be decided once**: the coarse-pointer font size (16 px,
because Safari zooms below it), the touch minimum (48, because `--touch` says 48), the top inset
(`env(safe-area-inset-top)`, because `viewport-fit=cover` is set), the ink contrast (4.5:1,
because the text is 10–13 px), the accent's single meaning (§6.8: selection and primary actions),
the two voices (§6.8: mono is the data voice and prose is never mono), the wrapper's timeout and
its error sentence. A rule decided in one component is not a rule — that sentence is already in
`test_static_contracts.py:78` and it is the reason this milestone exists.

The two CI-touching findings append **one** `svelte-check` job to the workflow structure M4.8
established. That is safe only after the red is fixed here, which is why they are at the end of
this milestone rather than the start of that one.

## What is broken today

repair. Every line reference was re-read against this tree (`m45` head `50753a3` plus the
uncommitted spec amendments); where a mitigation written before the 2026-09-03 decisions is now

### The shell's box

**1. The installed app's header lies under the status bar.**
[`dd27-standalone-header-under-status-bar`]
`app.html:5` sets `viewport-fit=cover` and `:12` sets
`apple-mobile-web-app-status-bar-style=black-translucent`, so the home-screen app's web view
starts at the physical top edge with the status bar drawn over it. The only `env(safe-area-inset-*)`
in the whole tree is `NavRail.svelte:92`'s bottom padding. `+layout.svelte:128-139` gives the
header `height: 54px; padding: 0 20px` and no top inset; the account chip
(`AccountChip.svelte:159-170`) is a 32 px control centred inside it, so on every notched iPhone
(status bar 47 px on the 11/12/13/14, 59 px from the 14 Pro on) it is entirely covered and a tap
there triggers scroll-to-top. `TitleDetail.svelte:255`, `:440` and `ModelRail.svelte:131`
hard-code `top: 54px` to the same height. **Should:** the header pads itself by the top inset and
grows by it; the two overlays offset by `calc(54px + env(safe-area-inset-top))`; the bare pages
(`login`, `account/password` at `padding: 24px`; `setup` at `40px 24px`) use
`max(24px, env(safe-area-inset-top))` / `max(40px, …)` for their top padding. `env()` is 0
everywhere else, so desktop and Safari-tab rendering do not move. **Do not remove
`viewport-fit=cover`** — NavRail's home-indicator padding depends on it.

**2. The 100vh shell hides the bottom tab bar under Safari's toolbar.**
[`fe-02-ios-safari-shell-100vh-and-input-zoom`]
`+layout.svelte:117-127` sets `.boot` and `.shell` to `height: 100vh`, with `main` scrolling
internally (`:173-178`) and the phone layout reversing the column so the nav is at the bottom
(`:181-188`). In an iOS Safari tab `100vh` is the *large* viewport — 745 px on an iPhone 13 —
while 664 px are visible with the toolbar expanded. The 61 px bar therefore sits inside the 81 px
hidden strip, and because the document is exactly the layout viewport nothing overflows, so
Safari never has a reason to collapse the toolbar. Every member's first session happens in a
Safari tab (install comes after sign-in, §3.1), and the surface switcher is invisible there.
`grep -rnE 'dvh|svh|fill-available' frontend/src` returns nothing. **Should:** the fallback pair
`height: 100vh; height: 100dvh;` on both rules — the same property twice, so iOS < 15.4 keeps
today's behaviour. **Not** `maximum-scale=1`, and **not** `-webkit-fill-available` on `body`
(it breaks the bare pages' `min-height: 100vh` centring). The fixed overlays are `bottom: 0` and
follow the layout viewport; leave them.

**3. Thirty-three form controls are 11–13 px, so Safari zooms on every focus.**
[`dd27-every-input-below-16px-triggers-safari-focus-zoom`]
`design.css:172-180` sets text inputs to `font-size: 13px`; the coarse-pointer block at `:193-210`
adds `min-height` only. Home's filter selects are 11 px (`routes/+page.svelte:474-481`), Rank's
controls 12.5 px (`rank/+page.svelte:352-362`). The markup now carries 33 controls (the review
counted 31; the tree has grown), and every one on the member path — login name and password, the
three password-change fields, the chip's PIN box, the account page's passkey label / PIN / tier
inputs, Home's search and three filters, Rank's filters, Tonight's guests and budget — is below
Safari's 16 px zoom threshold, and Safari does not zoom back out. The cascade matters: Svelte's
scoped `.controls select` is (0,3,1) and beats a bare global `select`, while the global
`input:not(…)×4` rule is (0,4,1) and beats scoped input rules. **Should:** `font-size: 16px` for
inputs inside the existing coarse block, plus `select, textarea { font-size: 16px }` there, plus a
coarse override next to `routes/+page.svelte:474` and inside `rank/+page.svelte`'s existing coarse
block at `:571-581` (which is deliberately last in that sheet — keep it last). **Do not** set
`maximum-scale=1` in `app.html`; that disables pinch zoom for everyone. Desktop sizes do not
change — 16 px is a touch-only rule.
*Stale detail:* the finding calls `tv/+page.svelte:128` "the only compliant control". Decision 165
deletes `/tv` entirely; it is another milestone's deletion and is out of scope here — do not
restyle it and do not count it.

**4. The account menu's links are the only phone path to /account and /admin, and they are 33–36 px.**
[`fec03-account-menu-links-are-the-only-phone-path-to-account-and-admin-and-miss-48px`]
`design.css:193-201` grows `.pill, .btn-primary, .btn-ghost, button, select, [role='button']` to

**5. The two full-bleed overlays cover the nav and exit through a 32 px glyph.**
[`fec04-fullscreen-phone-overlays-with-a-32px-exit-over-the-nav`]
`TitleDetail.svelte:253-278` is `position: fixed; top: 54px; right: 0; bottom: 0;

48 px tall, 32 px wide, 67 % of the §6 floor on its narrow axis. **Should:** `min-width:
var(--touch)` on both `.close` rules. **Not** a global `min-width` in the coarse block — it would
break the shelf nudge chevrons and the block-counter ticks — and **not** raising NavRail above the
panels; the panel is meant to be modal on a phone.

**6. The first-boot progress bar renders as five 48 px grey blocks on any touch device.**

`setup/+page.svelte:202-210` styles `.progress button { flex: 1; height: 3px; padding: 0 }` with

**7. Four assertions titled "48 px" assert 44.**
[`tq4-48px-rule-asserted-at-44-against-a-48px-token`]
`06-responsive.spec.js:44,45,52` and `13-rank.spec.js:332` use

### Dismissal, focus, and reasons that only exist on hover

*Scope correction:* the mitigation's other half — putting the Home selection in the URL (`?title=ID`)

### The two voices, the accent, and the weights

**11. The prose register wears the data face, and it is unreadable.**
[`cs-29-quiet-reasons-set-in-the-data-voice`] + [`fe-06-quiet-reasons-illegible-contrast`]
`design.css:101-106` defines `.why { font-family: var(--mono); font-size: 10.5px; color:
var(--ink-4) }` — the same face as `.data` at `:92-97`, differing by half a pixel. §6.8 assigns
JetBrains Mono to "every model number, ID and data annotation" and the file's own header (`:8-11`)
says using it for anything else "is a design bug". `.why` carries every one-line why in the app:
**106 elements across 25 files**, including whole explanatory paragraphs on the account, connectors
and Data pages. It is the largest §6.8 deviation by element count. On top of that, `--ink-4` is
`rgba(236,233,228,0.35)` and `--ink-5` `0.28`; recomputed here against `--ground #0d0d0f` and
`--card #141416`: **2.82 / 2.87** and **2.22 / 2.28**. WCAG AA wants 4.5:1 at these sizes and even
the 3:1 large-text floor is missed. `ShelfRow.svelte:179-181`'s `.caption` is the ink-5 case — a
why-line at 2.22:1, the darkest text in the app. **Should:** `.why` becomes `var(--display)` at
13 px; where a why-line embeds a model number that fragment is wrapped in `.data`, as `ModelNote`
already does. `--ink-4` rises to `0.55` (5.35 / 5.29) and `--ink-5` to `0.50` (4.60 / 4.58).
`.data` keeps the mono face, 10 px, 11 px on coarse pointers. `RateClassBalance.svelte:148-158`'s
`.warn` then drops **both** its `color: var(--ink-2)` and its `font-family: var(--mono)` overrides,
so the register is one thing rather than two.
*Two corrections to the written mitigations.* (a) `fe-06` says "keep the mono face"; `cs-29` says
the face **is** the violation. `cs-29` wins — §6.8 and design.css's own contract are explicit, and
`fe-06`'s coarse-pointer `.why { font-size: 12px }` is then subsumed by the 13 px display size.
(b) `fe-06` proposes `--ink-5 ≈ 0.45` **and** a guard asserting ≥ 4.5:1; 0.45 measures 3.93 and
fails that guard. 0.50 is the smallest value that satisfies both. (c) `fe-06` also asks for a
larger `.why` on `tv/+page.svelte`; decision 165 deletes that route — skip it.

**12. Nothing in the app is ever bold.**
[`fe-08-bold-font-faces-point-at-400-file`]
`frontend/static/fonts/fonts.css:26-64` declares Space Grotesk 500 and 700 (and JetBrains Mono 500
at `:86-104`) whose `src` is the **400** file; `ls frontend/static/fonts` shows only
`*-400-*` woff2. Because a face with the requested weight is declared, browsers use it as-is and
never synthesise, so the wordmark (`+layout.svelte:140-142`, `font-weight: 700`), every heading,
`<strong>` in the passkey welcome and `.btn-primary` (600) all render regular. `fonts.css:4` says
"Regenerate with `ops/fetch-fonts.py`"; `ops/` has no such file. **Should:** ship the real weights
— an `ops/fetch-fonts.py` that pulls the 500/700 latin + latin-ext woff2 subsets and rewrites
`fonts.css` from a template, with the files committed (self-hosting is load-bearing: the app must
render on the LAN with no route to the internet, `app.html:13-15`). If the implementing agent has
no network, the honest interim is to **delete the 500/700 blocks** so the browser synthesises bold
— a visible change either way, and better than a face that lies. Either way, a guard asserts every
`src: url(/fonts/…)` exists on disk and that the filename's weight matches the rule's
`font-weight`.

[`cs-28-ember-accent-spent-on-six-non-selection-roles`]
§6.8: "one ember accent #c8613a spent on selection and primary actions". `var(--ember)` is a fill
on things that are neither, at: `AccountChip.svelte:177` (the identity avatar),

accent #c8613a", and its named test (`test_static_contracts.py:58-64`) asserts
`set(ember_uses) <= {"ember", "facet-mood"}` — the row forbids what its own test permits, and the

selection-and-primary-action allowlist. `AccountChip.svelte:286` (the show-model switch track when

*The one that needs saying:* the mitigation offers "either recolour `--facet-mood` or amend the

### The wire

**14. Session loss is never recognised.**
[`fe-04-no-global-401-handling-session-loss`]
`api.js:36-69` throws `ApiError` on 401 and nothing above reacts: there is no interceptor,
`+layout.svelte:50-53`'s guard `$effect` re-runs on pathname only, and `session.user` stays
populated from bootstrap. Each store maps the error into its own red banner
(`rate.svelte.js:235-251`, `tonight.svelte.js:93-96`, `rank.svelte.js:123-127`), so after a
rotated `SESSION_SECRET`, a restored backup or the hourly prune the person sees
`deps.py:22-31`'s "not signed in" / "session expired" on Rate, then Rank, then Home — with their
name still in the chip and Log out the only way out. `isUnauthenticated` is consulted only inside
`session.svelte.js:66,90`; `needsAdminReauth` and `needsPasswordChange` (`api.js:24-29`) have **no
production caller at all**, so an admin resetting a member's password leaves that member's live tab
printing `deps.py:40-44`'s sentence on every surface with no link to `/account/password`.
**Should:** handled once, in `api.js` — a module-level `onUnauthenticated` handler registered by
`+layout.svelte`'s `onMount`, called before the throw on a 401 whose path is not a credential
route, and `goto('/account/password')` when `err.needsPasswordChange`. The `ApiError` still throws,
so callers are unchanged, and `goto` stays out of `api.js` behind the handler so the module stays
DOM-free. Exempt paths, read off the routers: `/auth/login`, `/auth/switch`, `/auth/logout`,
`/auth/passkey/login` and `/auth/passkey/login/options`, `/auth/me`, and anything under `/setup/`.
`/auth/passkey/register*` is **not** exempt — a 401 there is a real session loss.
*Stale reference:* the mitigation says to "route the reauth case to fe-05's re-auth screen".
`fe-05` is not a live finding. The correct instruction: a 401 carrying `X-Spielplan-Reauth: admin`
(`deps.py:55-60`) must **not** sign the admin out and must not navigate; the shell's existing
banner (`+layout.svelte:29-32,101-109`) remains the only signal, and it stays stale until the next
bootstrap. That gap is named in "What this milestone does not do".

**15. An offline boot signs a live member out.**
[`fe-07-offline-boots-into-dead-login-page`]
`session.svelte.js:63-72` swallows `/config` and `/setup/state` failures into null but **rethrows**
anything from `/auth/me` that is not a 401 — after its `finally` has already set `booted = true`.
`+layout.svelte:43-46` awaits `bootstrap()` in `onMount` with no `try`/`catch`, so the onMount
guard is skipped, the promise rejects unhandled, and the already-armed `$effect` runs with
`user === null`: `landingRoute()` (`:116-121`) returns `/login` and the shell navigates there with
the session cookie untouched. Offline, the service worker serves the cached shell and what it
opens is a login form whose POST cannot leave the device, with no `online` listener to
re-bootstrap; `hasBundle` stays at its initial `false`, so the header prints "no bundle imported"
(`+layout.svelte:86-95`) — a claim the client never verified. On a first boot whose `/setup/state`
read fails, `setup` is null and the admin is sent to `/login` instead of `/setup`. **Should:** a
non-401 `/auth/me` failure means "unknown, not signed out" — caught, `session.offline = true`,
`session.user` left as it was, not rethrown; the 401 branch stays exactly as it is, because that
*is* a sign-out. `hasBundle` becomes tri-state (null = not read) or the header pill is gated on
`!session.offline`. `+layout.svelte` wraps the onMount await, `guard()` returns early while
offline, an "appliance not reachable — retry" card renders, and `window.addEventListener('online',
bootstrap)` is registered. **Do not** extend the service worker to cache `/api`.

**16. A request that never settles parks the surface forever.**
[`fe-lc-01-no-timeout-permanent-busy`]
`api.js:36-43` sets no timeout and no `AbortSignal` (the `signal` option is plumbed and no caller
passes one), and every surface's single-flight guard is a boolean cleared in a `finally`
(`rate.svelte.js:253-266`, `tonight.svelte.js:254-256`). A stalled TCP connection — the ordinary
phone-leaves-the-house failure — parks `busy` at true forever: every subsequent tap returns early,
nothing is sent, and `rate.error` stays `''`, so the surface looks alive and simply stops
answering. **Should:** a default deadline in `api()` — an `AbortController`, a `setTimeout` abort
at 10 s for ordinary calls, cleared in a `finally`, with an `AbortError` mapped to an `ApiError`
carrying a stated sentence so the existing `onError`/`fail` paths render "the network did not
answer — try again" instead of `''`. Three callers legitimately run minutes and pass an explicit
long override: `BundleImport.svelte:26` (`/admin/bundle/validate` and `/admin/bundle/import`) and
`admin/connectors/+page.svelte:127` (`/admin/connectors/jellyfin/sync`). **Do not** bolt

## Risks and gotchas

- **The six files are exclusive, and three findings live outside them.** The sequence guards touch
  `rank.svelte.js`, `routes/+page.svelte` and `tonight.svelte.js`; the logout clears reach into the
  stores; the sweeps touch nine components. Land those steps **after** M4.9 / M4.10 / M4.12 merge
  and re-read the functions first — the line numbers quoted here are from the `m45` head.
- **`feroutes-logout-has-no-catch` is filed against another milestone and lives in this
  milestone's `logout()`.** Fixing it is inside `fe-12`'s own mitigation (without the catch, a
  failed POST skips every clear), so do it here — but check `git log`/the diff first so it is not
  written twice, and tell that milestone's owner it is discharged.
- **Only one milestone can be `current_milestone`.** Write the rows first; raise it last.
- **Renaming a registered test breaks the build.** `test_spec_coverage.py` matches Playwright
  titles literally. `02-shell.spec.js`'s dead-link test gets a new title — the row must carry the
  new one, in the same commit.
- **Vitest is invisible to the coverage contract.** Anything you intend to *count* has to be a
  pytest function or a Playwright title.
- **Raising the 44 → 48 assertions makes shipped-milestone e2e tests red.** Land them in the same
  commit as the CSS that satisfies them, or CI is red for every other milestone landing in
  parallel.
- **Specificity, not intent, decides the 16 px rule.** The global input rule is (0,4,1) and wins
  over scoped input rules; a scoped `.controls select` is (0,3,1) and wins over a bare global
  `select`. Rank's coarse block at `rank/+page.svelte:571-581` is **last in its sheet on purpose**
  — its selectors tie on specificity with the base rules above it, so source order decides. Keep it
  last, and let the e2e sweep tell you which scoped overrides are still needed rather than guessing.
- **`env(safe-area-inset-*)` is zero on every engine the suite runs**, so a wrong `calc()` will not
  fail a browser test. The static guard is the only check; write it to assert the *rule*, not the
  file's byte content.
- **`location.reload()` after `goto('/login')`** is the house pattern (`AccountChip.svelte:56`) and
  it will interact with the e2e helpers — `signedIn()` re-enters through `/login`, so a reload
  mid-navigation can race an assertion. Reload after the navigation resolves.
- **Adding `@types/node` changes `package-lock.json`**, which both `npm ci` in CI and the frontend
  Docker build have to see. The cast avoids that for one error; prefer it.
- **`ruff format` is not enforced and line length is 108 on purpose** (spec sentences are quoted
  inline). Do not reformat adjacent code — `CLAUDE.md`: every changed line traces to the request.
- **Keep console and test output ASCII.** Windows cp1252 consoles crash on decorative glyphs; the
  failure messages this milestone adds will be read on one.
- **Cite the clause.** §6 preamble, §6.8, §3.1, §3.2, proposals 126/127/130/131, decisions 164/165/166
  — a comment that cannot cite its clause reads as off-convention here, and half of these changes
  look like taste until the sentence is quoted next to them.
