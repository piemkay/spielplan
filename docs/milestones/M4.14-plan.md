# M4.14 — bundle import and artifact custody: take the 127 s off the request path, and make every refusal land in the report

> ## DECISIONS TAKEN SINCE THIS PLAN WAS WRITTEN
>
> This plan was drafted while the questions below were still open, so it may present two branches or defer to "an owner decision". **It no longer does.** The rulings are binding; where the plan below offers a choice this section has already made, follow this section. Full reasoning and evidence are in [`ROADMAP-to-M5.md`](ROADMAP-to-M5.md#decisions-taken).
>
> **Decision 171 — Should a models-only re-import load the curated ledgers (corrections_v1.tsv, seed_list.json, adjudications_v1.tsv, the axis TSVs), or skip them loudly?**  
> Load the four curated ledgers on every import, models-only included, from one function called once outside the `if db is not None` block; the vocabulary tier itself (facets, terms, aliases) stays seed-only, because its loaders are ON CONFLICT DO NOTHING and decision 163 pins the version anyway. Three guards are part of the ruling, not follow-up work: load_seed_list must DELETE the table first and then skip — and count in the report — any entry naming a title this install never seeded, because seed_list.title_id is a NOT NULL FK to title(id) and an unknown id aborts the whole import; _load_adjudications must gain the 'parses to nothing, do not replace' guard load_corrections already has, or a present-but-empty ledger silently wipes 828 curated verdicts; and the version the ledgers are written under must be the install's active dna_vocabulary version when the bundle names none, not the `or "v1"` literal. An absent ledger file stays a warning that changes nothing — omission must never be destructive.
>

**This milestone is not in §12.** It exists because §5.3 files bundle import as a worker job
("Bundle import validation + hot swap | admin action | minutes") and it is not one — it is a
127-second `await` inside `POST /api/admin/bundle/import`, on the backend's event loop, behind an
ingress that cuts at 100 s. And because §10 promises "a migration report (counts per table,
validation failures, vocabulary version)" for a validate step that today can hand the operator a
`UnicodeDecodeError`, a `ForeignKeyViolationError`, a `tarfile.ReadError` or an empty
`.unpacked-*` directory instead. Twenty of the thirty-two findings in scope are one defect class:
a refusal or a crash that leaves the tree, the row or the report in a state the next attempt
misreads. Decision 162 makes that class expensive in a way it was not before — content seeds
once, so the first content import is the only one the household will ever get, and a corrupted
seed that passes validation can only be undone by dropping the database.

## 1. Why these are one milestone

`importer/bundle.py`'s `validate()` / `refuse_on_install_state()` / `import_bundle()`,
`importer/validate.py`'s rule block, and `api/artifacts.py` are one machine: open, refuse, stage,
load, rebuild, flip. Nothing else in the codebase edits them. Twenty of these findings insert a
new refusal into the same thirty lines from different directions — `cs-06` before
`validate_id_partition`, `dd09-fk-not-null` inside `validate_content`, `cs-36` and
`dd09-validate-says-ok-for-unsafe-bundle-version` inside `refuse_on_install_state` and
`_read_bundle_identity`, `dd10-*` inside `Bundle.open` — and each of them is a two-line diff that
conflicts with the other four if they are scheduled apart.

The relocation forces the rest. `POST /import` is either a synchronous handler that returns a
report or a 202 that queues a job and hands back a version to poll. Those are incompatible
response shapes: `BundleImport.svelte`'s `run()`, `ops/devstub.py`'s mirror of the route,
`e2e/specs/01-first-boot.spec.js`'s "import runs the swap sequence" test and
`test_devstub_contract.py` all encode one of them. Landing `perf-02` after twelve other diffs
means rewriting the call site twelve times; landing it before them means every other mitigation's
cited line numbers move under it. It goes in the same milestone, at a stated point in the order.

Three pairs are literally one repair. `imp-vocabulary-version-derived-four-ways` wants one
derivation of the vocabulary version; `cs-36` wants a refusal when no version is declared —
landed separately, the first makes the second's guard unreachable and the second hard-codes a
derivation the first is deleting. `dd10-partial-unpack-is-reused-as-a-bundle` and
`dd10-non-archive-file-500s-and-leaves-junk` are the same six lines of `_unpack`.
`dd11-seed-list-upsert-keeps-stale-tail` moved in from the read-layer work because its missing
`DELETE` is only reachable through the load path `dd11-models-only-import-drops-curated-ledgers-silently`
newly calls; fixing the second without the first ships a merge of two onboarding lists.

**Depends on:**

* **M4.7** — the worker job registry with a per-job timeout, stop grace and a persisted
  `job_run` row. The import *becomes* that row. Today `worker.py`'s `JOBS` tuple carries no
  persistence at all (`_tick` at `worker.py:307-314` swallows exceptions into the log) and
  `grep -rn job_run` over the repo returns nothing.
* **M4.9** — the facet/vocabulary rule the loader applies, which decides what `validate` must
  check before a `dna_tag` row is written.
* **M4.13** — `ArtifactStore`'s single resolver and its `bundle_version` keyword. The importer
  cannot thread its *staged* version down until one exists;
  `models/artifacts.py:85-88`'s own vocabulary derivation is one of the four this milestone
  collapses.

## 2. What is broken today

Every line reference is against `50753a3` plus the uncommitted spec amendments, verified by
reading the file.

### 2.1 The import is a two-minute request [perf-02, ops-06]

`api/artifacts.py:88` — `report = await bundle_import.import_bundle(conn, b, settings().artifacts_dir)`
inside the route. Inside it: `shutil.rmtree`/`copytree` of the artifacts tree
(`bundle.py:561-564`), the COPY generators (`load.py:306` `_rows` is a plain generator over
`db.execute` fed to `copy_records_to_table`), `repair_mojibake` over all 485,602 review bodies
(`reviews.py:100-110`), and `placement.run_rebuild` — numpy MAP refits and a torch forward pass —
at `bundle.py:639-644`, all before the flip and all inside one transaction. `grep -rn
"to_thread|run_in_executor" backend/spielplan` hits only `backup/nightly.py`. The M4.5 close-out
measures 127 s on the real bundle (`docs/milestones/M4.5-plan.md:323`).

For those two minutes `/api/health` (`app.py:98-112`, which acquires a pool connection on the
same loop) does not answer, against a `HEALTHCHECK --interval=30s --timeout=5s --retries=5`
(`ops/backend.Dockerfile:58-59`). §2 puts the origin behind the operator's existing
Traefik + Cloudflare; a proxied request with no origin response is cut at 100 s. So the operator
sees a red failure for an import that completes, retries, and gets `seed-once`: *"movie data was
already seeded by bundle …"* (`bundle.py:443-450`) — which reads as corruption.

**Should be:** §5.3's own row. `POST /import` validates (measured at 1.0 s on the real bundle) and
returns 202; the load runs in the worker, which already holds torch and the Backbone; the Data tab
polls. Not `asyncio.create_task` in the backend — that keeps the CPU on the request loop and keeps
torch resident there (see 2.21).

### 2.2 Nothing serialises two imports [data-09]

The `already == 'active'` check (`bundle.py:542-547`), the install-state refusals
(`bundle.py:407-450`) and the `rmtree` + `copytree` (`bundle.py:561-564`) all run outside the
transaction and outside any lock; `grep -rn advisory backend/spielplan` is empty. Reproduced
twice: with a 0.15 s stagger on the same version the second request passed every check (the
first's row was uncommitted), deleted and re-copied the tree the first was about to hand to
`run_rebuild`, then died on `UniqueViolationError title_alias_pkey`. With two different seed
versions, `artifact_bundle` held only `seed-a` while `/data/artifacts` held both — a staged tree
with no row that nothing ever cleans up.

**Should be:** one session-level `pg_try_advisory_lock` taken before the install-state checks,
released in a `finally`; the loser gets a report line, not a Postgres constraint name.

### 2.3 The destructive button re-arms itself after a failure [fe-lc-11]

`BundleImport.svelte:62` — `disabled={busy || phase === 'idle' || (report && !report.ok)}`. On a
502/504/timeout the catch at `:30-33` sets `report = err.detail?.report ?? null`, and `null &&
…` is falsy, so the button is live again the instant the request fails. It is also live after a
successful import (`phase === 'imported'`, `report.ok === true`). `api.js:36-43` sets no timeout,
so the browser decides when the admin is told it failed.

**Should be:** enabled only on a positive report, and never in a state where the outcome is
unknown.

### 2.4 BUNDLE.json ships 42 hashes and the importer reads none of them [cs-06]

Measured on `v20260828`: `files` is a 42-entry map of `{bytes, sha256}`, `validations` is 68 rows
with an `ok` flag, `total_bytes` is 1,042,461,726. `_identity()` (`bundle.py:164-180`) parses the
file and `_manifest_of()` (`bundle.py:681-689`) stores the whole blob, but only `bundle_version`,
`vocabulary_version` and (for the Data tab's title count) `tables.title` are ever read.
A zeroed `equating_map.json` validates clean; a truncated `reviews.sqlite` validates then dies as
an uncaught `sqlite3.DatabaseError` inside the import transaction; a truncated `content.sqlite`
makes `validate` itself a 500. `artifact_bundle_one_seed` (`0015_seed.sql:121`) then makes the
redo impossible.

I re-verified the hash pass costs nothing: **42 files, 1.04 GB, 0.7 s** on the development box
with a warm page cache (budget it as seconds on the reference box's disk, not minutes). One
detail the implementation must handle: `BUNDLE.json` is the only file on disk that is *not* in its
own `files` map — it cannot list its own hash — so present-but-unlisted has exactly one legitimate
member.

**Should be:** every listed file stat'd and hashed before a row is written; present-but-unlisted
and listed-but-missing reported under the same rule; any `validations` entry with `ok: false`
surfaced as a failure; `BUNDLE.json`'s `tables` counts compared against `report.table_counts`
after the load.

### 2.5 A half-extracted archive is reused as a bundle, and a plain file is a 500 [dd10-partial-unpack-is-reused-as-a-bundle, dd10-non-archive-file-500s-and-leaves-junk]

`bundle.py:195-212`:

```python
def _unpack(archive: Path) -> Path:
    target = archive.parent / f".unpacked-{archive.stem}"
    if target.is_dir():
        return _single_child(target)
    target.mkdir(parents=True)
    ...
        tar.extractall(target, filter="data")
```

`target.mkdir` runs *before* `tarfile.open`, and there is no cleanup on any exception. Every
failure mode — a truncated transfer, disk full, a traversal member refused by `filter="data"`
after earlier members landed, a backend restart — leaves a tree the retry opens as a real bundle.
Reproduced with the real corpus tar cut at 90 %: the first `validate` raised, the second returned
`ok=True` over a 332-of-436 MB `reviews.sqlite`. With the fixture cut inside `reviews.sqlite` the
import returned 200, flipped the seed active and loaded zero review bodies behind a single warn
(`reviews.py:116-119` makes a missing `review` table a warn, not a failure). Keying on `stem`
also makes `v1.tar` and `v1.tgz` share one tree.

A non-archive file is the same door: `bundle.py:150` treats every non-directory as an archive, the
`ReadError` escapes as HTTP 500 (`BundleImport.svelte:68` renders a bare string), an empty
`.unpacked-README/` is left behind, and the second click is diagnosed as
*"this is a models-only bundle and the install has no content"* — a decision-162 refusal for a
typo. **The `.tar` and `.tar.zst` paths have no test at any layer.**

**Should be:** extract to `.unpacking-<archive.name>`, `rmtree` on any exception, `os.replace`
into `.unpacked-<archive.name>` only after `extractall` returns — so a final directory can only be
a complete extraction. A `BundleOpenError` the route maps to 400. A `PRAGMA quick_check` on both
sqlite files during validation. **No "force re-extract" flag, and seed-once is not weakened.**

### 2.14 The vocabulary version is derived four ways, and the refusal it feeds is skipped [cs-36, imp-vocabulary-version-derived-four-ways]

Four derivations: `bundle._vocabulary_version` (`bundle.py:183-192`) prefers a `BUNDLE.json` key
and falls back to the lexicographically last `dna_vocab/` subdirectory; `validate.py:403-405`
repeats it; `ArtifactStore.open` (`models/artifacts.py:85-88`) prefers `artifacts/manifest.json`
and falls back to `sorted(glob("*"))[-1].name` — **including files**; `refuse_on_install_state`
reads `dna_vocabulary.imported_at` (`bundle.py:455-457`). Probed: with `v1`, `v2`, `v10` present
both bundle-side readers pick `v2`; with a stray `zz_notes.txt` in `dna_vocab/` the store reports
`vocab_version = 'zz_notes.txt'` while `Bundle` says `v2`.

Decision 163's refusal is `if active_vocab and bundle.vocabulary_version and they differ`
(`bundle.py:458`). **I confirmed the real `BUNDLE.json` has no `vocabulary_version` key** — its
sixteen top-level keys are `bundle_version, created_at, spec, tables, filtered_tables,
display_only_tables, frozen_rating_source_ids, nullable_pk_columns, nullable_pk_note,
watchlist_note, with_reviews, with_text_components, validations, files, source_provenance,
total_bytes`. So the refusal rests entirely on a directory listing, and decision 162 narrows every
future re-import to a models-only bundle, which is precisely the bundle least likely to ship a
`dna_vocab/` tree. Omit it and the version resolves to `None`, the refusal is skipped, `validate`
emits a warning, and a v2-trained backbone lands on a v1 install — the silent catastrophe
decision 163 exists to convert into a readable refusal. The row also records
`vocabulary_version` NULL.

### 2.20 The Backbone cache survives a same-version restage [ml10-backbone-cache-stale-after-same-version-restage]

## 3. Owner decisions this milestone cannot take alone

Three, and each blocks a specific step. Ask them before writing the code, and record the answers
as numbered entries in `docs/spec-v2.2-proposals.md` — CLAUDE.md requires work to cite its clause,
and a comment citing "the review" points at nothing.

**Decision α — does a models-only bundle carry the curated ledgers? (2.15)**
§4.3 says `corrections_v1.tsv` *"travels with the bundle and is applied at every derive"*, and
decision 162 makes the models-only bundle the only one that will ever arrive again. Two coherent
answers: **(A)** the model path loads `corrections_v1.tsv`, `seed_list.json`,
`adjudications_v1.tsv` and the axes — but never `load_vocabulary`'s term tables, `load_tags` or
`load_projected`, which are the content tiers decision 162 forbids re-importing; or **(B)** the
ledgers are seed-only and the report `warn`s for each file present and not loaded, naming it and
citing decision 162. Both are honest; only silence is not. The step and the coverage row are
written the same either way — what changes is the assertion.

**Decision β — is an unknown backbone row a refusal? (2.16)**
Either the corpus's catalogue is frozen at export time (keep the refusal) or it is not (treat
`absent` on a models-only bundle as a note carrying the count, keep `mismatched` and `unparsed`
as failures, and add the reverse check that is the real merge signal: every installed
`origin='bundle'` title the *active* backbone covers must still be covered by the new one). The
alternative — having `mdc export-bundle` take an id list from the install — couples the two
projects and is heavier. This decision rewrites a registered test
(`test_an_identity_naming_a_title_the_spine_does_not_carry_is_refused`), so it must precede the
code.

**Decision γ — are bundle rows prunable, or are they provenance? (2.18)**
This one gates the migration. Recommended: **never deleted** — a `BEFORE DELETE` trigger that
RAISEs unless `state IN ('staged','failed')`, with `user_vector`'s `SET NULL` kept as the
documented exception. If pruning is wanted instead: `session.bundle_version` drops NOT NULL and
gains `ON DELETE SET NULL` (votes and outcomes are vocabulary-independent facts,
`0013_tonight.sql:46-48` — **not** CASCADE), plus a trigger refusing deletion of the active row.
Either way the placement hole closes with the same `CHECK ((placement = 'unplaced') =
(placement_bundle IS NULL))`, and that CHECK needs `placement`/`placement_at` added to
`DROPPED_COLUMNS` in `backup/movie_data.py` first or restored archives will not satisfy it.

## 9. Risks and gotchas

**The line numbers in the findings move under you.** Every mitigation cites `bundle.py` and
`validate.py` at `50753a3`. Waves A–D insert refusals into both files; by Wave D none of the
original numbers hold. Work from the function names, not the line numbers, and re-grep before each
step.

**`artifact_bundle_one_seed` is a partial unique index on `kind`, and `kind` defaults to
`'seed'`.** Any row you insert into `artifact_bundle` for a not-yet-successful import claims the
one-and-only seed slot, permanently. This is why E1 keeps the row where it is. If you find
yourself wanting a placeholder row, that is the trap.

**`placement.assert_staged` reads `artifact_bundle.state`.** It requires `'validated'` or
`'active'` (`reconcile.py:530-533`). Any new state, and any reordering that runs the rebuild before
the row is written, breaks it — loudly, which is the good case.

**Never edit an applied migration.** `0001`, `0008`, `0009`, `0013` and `0015` all touch
`artifact_bundle` and all are checksummed; a mismatch is a hard startup error in `db/migrate.py`.
Add a new numbered file, and see §5 on the number.

**Integration tests skip silently without `TEST_DATABASE_URL`.** A green no-DB run has not run
half of this milestone. Bring Postgres up with
`docker compose -f docker-compose.yml -f ops/compose.dev.yml up -d db` — the overlay is never
auto-loaded, so pass both `-f`. The PGlite schema tests skip without
`backend/tests/pglite/node_modules`.

**Never run bare `pytest` from the repo root.** The config lives in `backend/pyproject.toml` with
`asyncio_mode=auto`; without the path argument the async tests error.
`backend/.venv/Scripts/python -m pytest backend/tests -q`.

**`e2e/specs/05-milestones.spec.js` fails by design when a surface ships.** Nothing in this
milestone ships a new surface, but the Data tab gains a state (`artifacts_missing`) and a phase —
check whether a placeholder assertion covers them before assuming the failure is a regression.

**`playwright test` against a used stack fake-passes.** `01-first-boot.spec.js` is a first-boot
spec; only `npm --prefix e2e run fresh` (`= node e2e/run.mjs`, two phases plus a backend restart)
actually exercises it. `e2e/reset.mjs` drops the database and wipes `data/artifacts`.

**Keep console and test output ASCII.** F1 is exactly this rule; do not reintroduce the glyph
anywhere the exit script or a failing assertion will print it. The Svelte glyph map at
`BundleImport.svelte:20` is a UI string and stays.

**Line length is 108 on purpose** so spec sentences can be quoted inline without wrapping.
`ruff format` is not enforced — do not reformat these two files wholesale while editing them; the
diff has to stay readable, and a reformatted `bundle.py` makes every one of the thirty-two
findings unreviewable.

**Comments argue why and cite the clause.** `bundle.py` and `validate.py` are the densest
example of that convention in the codebase — `validate.py:65-77`'s `_guard` docstring, and
`bundle.py:236-251`'s. New refusals that do not carry the measured fact behind them will read as
off-convention next to their neighbours.

**Two of the findings' own mitigations are stale against this tree, and are corrected above rather
than followed:** `perf-02`'s new `'importing'` state (superseded by M4.7's `job_run`; see E1) and
`ops-06`'s `asyncio.create_task` fallback (ruled out by `perf-02` and `perf-06`). One comment is
stale in the source itself and is corrected in C5: `validate.py:666-668` says `mdc export-bundle`
does not write `title_identity`, and as of `movie_data_curator@3666eaa` it does — what has not
